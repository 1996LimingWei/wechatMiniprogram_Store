## 2. 生产部署

### 2.1 基础要求

- JDK 25。
- MySQL 8.0，字符集 `utf8mb4`。
- Redis 7.x。
- HTTPS 域名，至少包含后端 API 域名、管理后台域名和小程序 request 合法域名。
- 对象存储或挂载目录，生产默认使用 `material.storage.provider=mounted`。
- 微信小程序正式 AppID/AppSecret。
- 微信支付商户号、商户私钥、平台证书、API v3 Key。
- 快递 100 企业 customer/key。

### 2.2 后端构建

```powershell
cd D:\MiniProgram\shop-backend
mvn -pl shop-server -am clean package
```

构建产物：

```text
shop-backend/shop-server/target/shop-server-1.0.0-SNAPSHOT.jar
```

### 2.3 数据库迁移

生产禁止重新执行 `sql/init.sql` 覆盖已有库。首次部署或升级必须执行增量迁移：

```powershell
cd D:\MiniProgram
scripts/migrate-db.ps1 -Database shop -MysqlContainer <mysql容器名> -MysqlUser <用户> -MysqlPassword <密码>
```

生产启动会检查 `schema_migration_history`，当前必需迁移版本为 `20260816_12`。未执行到该版本时，生产/预发布服务会拒绝启动。

### 2.4 后端环境变量

必须配置以下变量，空值视为不合格：

```text
SPRING_DATASOURCE_URL=jdbc:mysql://<host>:3306/shop?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
SPRING_DATASOURCE_USERNAME=<数据库用户>
SPRING_DATASOURCE_PASSWORD=<数据库密码>
SPRING_REDIS_HOST=<Redis地址>
SPRING_REDIS_PASSWORD=<Redis密码>
WEB_CORS_ALLOWED_ORIGIN_PATTERNS=https://<管理后台域名>
APP_EXTERNAL_BASE_URL=https://<后端API域名>

WX_MA_APPID=<客户小程序AppID>
WX_MA_SECRET=<客户小程序AppSecret>
WX_MA_MOCK_ENABLED=false

WECHAT_PAY_ENABLED=true
WECHAT_PAY_APP_ID=<客户小程序AppID>
WECHAT_PAY_MCH_ID=<微信支付商户号>
WECHAT_PAY_MERCHANT_SERIAL_NO=<商户证书序列号>
WECHAT_PAY_PRIVATE_KEY_PATH=<服务器商户私钥路径>
WECHAT_PAY_API_V3_KEY=<32字节APIv3Key>
WECHAT_PAY_PLATFORM_CERTIFICATE_PATH=<微信支付平台证书路径>
WECHAT_PAY_NOTIFY_URL=https://<后端API域名>/app-api/pay/wechat/notify
WECHAT_PAY_REFUND_NOTIFY_URL=https://<后端API域名>/app-api/pay/wechat/refund-notify

TRADE_REFUND_PROVIDER=wechat
TRADE_LOGISTICS_PROVIDER=kuaidi100
KUAIDI100_CUSTOMER=<快递100customer>
KUAIDI100_KEY=<快递100key>

MATERIAL_STORAGE_PROVIDER=mounted
MATERIAL_STORAGE_ROOT=<服务器素材目录>
MATERIAL_PUBLIC_BASE_URL=https://<素材访问域名>
```

### 2.5 管理后台部署

```powershell
cd D:\MiniProgram\shop-admin
corepack pnpm install --frozen-lockfile
corepack pnpm build
```

将 `shop-admin/dist` 部署到 Nginx 或静态托管服务。生产环境不得包含 `localhost`、`127.0.0.1` 或代理目标。

### 2.6 小程序发布

- 设置 `VUE_APP_API_BASE_URL=https://<后端API域名>/app-api/`。
- 微信后台配置 request/upload/download 合法域名。
- 使用 HBuilderX 编译微信小程序。
- 使用微信开发者工具上传体验版。
- 体验版通过后提交审核。

## 3. 回滚方案

### 3.1 应用回滚

1. 保留上一个可用后端 JAR 或镜像版本。
2. 停止当前后端实例。
3. 启动上一版本后端。
4. 检查 `/actuator/health`。
5. 在后台“交易管理 / 运行监控”检查数据库、Redis、支付回调、退款回调、任务告警。

### 3.2 管理后台回滚

1. 保留上一版 `dist` 目录压缩包。
2. 将当前静态目录替换为上一版。
3. 刷新浏览器并重新登录后台。
4. 验证订单列表、商品列表、售后列表、运行监控页面可访问。

### 3.3 数据库回滚

数据库回滚不直接删除迁移。出现严重问题时按以下顺序处理：

1. 停止后端写流量。
2. 使用上线前备份恢复到临时库。
3. 对比生产库和临时库差异。
4. 由负责人确认是否整体恢复生产库。
5. 恢复后重启后端并执行核心验收。

## 4. 运维巡检

每天检查：

- 后台“交易管理 / 运行监控”：数据库、Redis、告警、定时任务。
- 支付异常工作台：是否有未处理支付异常。
- 退款异常工作台：是否有未处理退款异常。
- 日终对账：前一日批次是否生成，差异是否处理。
- 订单履约：待发货订单是否积压。
- 素材目录：磁盘空间是否充足。

每周检查：

- 管理员账号和角色权限。
- 高风险操作审计。
- 数据库备份文件可用性。
- 生产配置是否出现本地地址、默认密码或 Mock 开关。

## 5. 数据库备份恢复

### 5.1 备份

```powershell
cd D:\MiniProgram
scripts/backup-mysql.ps1 -MysqlContainer <mysql容器名> -Database shop -MysqlUser <用户> -MysqlPassword <密码>
```

备份文件应保存到受控目录，并至少保留最近 7 天。

### 5.2 恢复

```powershell
docker exec -i <mysql容器名> mysql -u<用户> -p<密码> shop < <备份文件.sql>
```

恢复后必须检查：

```sql
SELECT COUNT(*) FROM schema_migration_history WHERE version = '20260816_12';
SELECT COUNT(*) FROM sys_admin_user WHERE status = 1 AND deleted = b'0';
SELECT COUNT(*) FROM trade_order WHERE deleted = b'0';
```

## 6. 管理后台使用手册

### 6.1 登录与权限

- 超级管理员负责账号创建、角色授权和敏感配置。
- 商品运营负责商品、分类、素材、营销、内容。
- 订单客服负责订单、发货、物流、售后查看和订单备注。
- 售后审核负责售后同意、拒绝、退货收货和退款同步。
- 财务负责支付异常、退款异常和日终对账。
- 只读角色只能查看，不允许业务写操作或敏感导出。

### 6.2 商品维护

1. 上传素材。
2. 新建或编辑商品。
3. 配置 SKU、价格、库存、预警库存和商品图片。
4. 上架商品。
5. 小程序检查商品列表和详情。

### 6.3 库存维护

- 单个 SKU 可人工调库存。
- 批量调库存必须填写原因。
- 库存流水可用于追溯初始库存、下单扣减、取消回补、退款回补和人工调整。

### 6.4 订单履约

1. 在订单列表筛选“待发货”。
2. 点击发货，选择物流公司并填写物流单号。
3. 系统校验物流公司编码和单号。
4. 发货后订单变为待收货。
5. 用户可在小程序查看物流轨迹。

### 6.5 售后与退款

1. 用户提交售后申请。
2. 售后审核人员查看申请原因和商品明细。
3. 仅退款可直接同意或拒绝。
4. 退货退款需等待买家填写退货物流，后台收货后再退款。
5. 退款进入可靠任务；成功、处理中、失败都会在退款详情展示。
6. 异常退款进入退款异常工作台，可人工同步、重试或处理。

### 6.6 财务对账

1. 每日检查日终对账批次。
2. 对账差异按类型查看本地金额和渠道金额。
3. 可导出 CSV。
4. 差异处理必须填写备注。

## 7. 商品导入模板说明

后台入口：商品管理 / 商品列表 / 下载导入模板。

导入要求：

- 商品名称必填。
- 分类必须存在且启用。
- SKU 编码建议唯一、可追踪。
- 价格使用元，导入后后端统一转分保存。
- 库存必须为非负整数。
- 图片 URL 必须是素材库可访问地址或客户认可的外部 HTTPS 地址。
- 导入前先使用少量数据试导入。

## 8. 发货导入模板说明

后台入口：交易管理 / 订单管理 / 批量发货模板。

导入要求：

- 订单号必须存在且处于待发货。
- 物流公司必须为当前支持公司之一。
- 物流编码必须与物流公司一致。
- 物流单号仅支持 6 至 32 位字母、数字或连字符。
- 批量导入结果会展示成功数、失败数和逐行错误原因。

## 9. 微信支付配置说明

微信支付必须满足：

- `WX_MA_APPID` 与 `WECHAT_PAY_APP_ID` 一致。
- 支付回调地址为 HTTPS：`/app-api/pay/wechat/notify`。
- 退款回调地址为 HTTPS：`/app-api/pay/wechat/refund-notify`。
- API v3 Key 为 32 字节。
- 商户私钥和平台证书只放服务器安全目录，不提交 Git。
- 真实验收见 `docs/acceptance/v1.0-wechat-pay-refund-acceptance.md`。

## 10. 快递 100 配置说明

快递 100 必须满足：

- `TRADE_LOGISTICS_PROVIDER=kuaidi100`。
- `KUAIDI100_CUSTOMER` 和 `KUAIDI100_KEY` 使用客户正式账号。
- 查询会传物流公司编码、物流单号和收件手机号。
- 成功查询后本地缓存 30 分钟。
- 供应商失败时页面展示友好提示，并优先回退最近缓存。
- 真实验收见 `docs/acceptance/v1.0-logistics-acceptance.md`。

## 11. 小程序提审资料清单

- 小程序 AppID。
- 小程序名称、头像、服务类目。
- 隐私保护指引。
- 用户协议、隐私政策、售后政策页面。
- 客服能力开通。
- request/upload/download 合法域名。
- 体验版二维码。
- iOS 与 Android 真机核心链路截图。
- 详见 `docs/acceptance/v1.0-miniapp-review-checklist.md`。

## 12. 客户验收清单

客户验收至少覆盖：

- 登录后台。
- 维护商品、素材、分类、SKU、库存。
- 小程序浏览商品、下单、支付。
- 后台发货，小程序查看物流。
- 用户确认收货。
- 用户申请售后。
- 后台同意退款和拒绝售后。
- 微信退款成功、处理中、失败异常。
- 日终对账生成、导出、差异处理。
- 高风险审计可追踪。
- 运行监控可查看。

## 14. 已知限制

- 客户正式 AppID、微信支付商户资料、快递 100 账号和真实物流单号未提供前，不能完成真实渠道最终验收。
- Docker Desktop 当前在本机不可用时，数据库空库迁移重放只能等 Docker Engine 恢复后补跑。
- 在线依赖漏洞扫描依赖 NPM/Maven 审计源和 OWASP 漏洞库下载；本机 2026-08-16 尝试执行 15 分钟超时，需在网络稳定或 CI 环境中复跑并归档结果。
- v1.0 暂不包含积分、直播、拼团、复杂分销和正式付费会员权益。
- 管理后台生产账号必须由客户指定安全交付方式，不能使用默认密码。

## 15. v1.0 发布说明

- 小程序：登录、首页、分类、商品详情、购物车、下单、支付、订单、物流、售后、退款状态、协议政策、客服入口。
