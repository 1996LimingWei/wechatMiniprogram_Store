# 陕铺商城管理后台用户手册

> 适用版本：v1.1.0（2026-11-27 上线版本）
> 适用对象：店铺负责人、运营、客服、库管、财务、系统管理员
> 编写日期：2026-11-28

---

## 0. 阅读说明

### 0.1 本手册覆盖范围

本手册为**管理后台**（电脑浏览器访问）的操作，不涉及小程序买家端的使用方法。小程序的功能由后台配置驱动，后台改完保存后，买家刷新小程序即可看到最新内容。

### 0.2 书写约定

| 写法 | 含义 |
|---|---|
| `A → B` | 左侧菜单 A，再点子菜单 B |
| **粗体** | 按钮名、字段名、页签名 |
| ⚠️ | 有风险的不可逆操作，执行前务必确认 |
| 红色星号 `*` | 表单必填项，不填无法保存 |
| 「」 | 页面上的原文提示或原文状态 |

### 0.3 金额与数量口径

- 后台所有金额输入框都以**元**为单位（如 `19.9`），系统内部按分存储，不会出现精度丢失；
- 商品「库存」指可售库存，订单支付成功后会锁定，发货后扣减；
- 「可售 / 锁定 / 当前库存」三者的关系见附录 C。

# 第一章 快速入门

## 1.1 系统能做什么

管理后台是商城的「总控台」，主要覆盖六件事：

| 大类 | 能做的事 |
|---|---|
| 商品 | 建商品、改价、改库存、上下架、批量导入导出、分类、素材、评论 |
| 交易 | 看订单、发货、改履约进度、处理售后与退款、处理支付异常、日终对账 |
| 营销 | 优惠券、满减活动、包邮与运费规则 |
| 内容 | 首页 Banner、频道入口、品牌、专题、用户反馈、可视化装修 |
| 会员 | 查看注册会员与基本信息 |
| 系统 | 店铺展示、新订单邮件通知、管理员账号、角色权限、审计日志 |

## 1.2 登录

1. 打开浏览器（推荐 Chrome / Edge 最新版），访问后台地址：`https://bhtjl.top/`；
2. 输入管理员**账号**与**密码**，点击登录；
3. 可以到右上角头像 → **修改密码**。

**密码规则**：至少 10 位、最多 72 字节，必须同时包含英文字母和数字。

**登录安全机制**：

- 连续输错密码达到上限后，账号会被临时锁定，页面会提示锁定截止时间；
- 被锁定后需由超级管理员在 `系统管理 → 管理员账号` 点 **解锁** 解除；
- 管理员修改角色、停用账号、重置密码后，该账号已登录的会话会立即失效，需要重新登录。

## 1.3 界面布局

```
┌──────────────┬────────────────────────────────────────────┐
│  左侧菜单树   │  顶部：页面标题 / 面包屑 / 右上角账号菜单        │
│              ├────────────────────────────────────────────┤
│  首页         │                                            │
│  商品管理     │            内容区（筛选栏 + 表格 + 分页）      │
│  交易管理     │                                            │
│  内容管理     │                                            │
│  会员中心     │                                            │
│  营销管理     │                                            │
│  系统管理     │                                            │
│  可视化装修   │                                            │
└──────────────┴────────────────────────────────────────────┘
```

- **左侧菜单**：只能看到当前账号有权限的菜单，看不到说明没有授权；
- **右上角账号菜单**：修改密码、退出登录；
- **列表页通用逻辑**：上方筛选 → 点 **搜索** 生效 → **重置** 清空条件；底部分页可切换每页条数（10 / 20 / 50）。

## 1.4 角色与权限

后台采用「角色 → 权限」模型：

1. 超级管理员在 `系统管理 → 角色权限` 建角色，按接口勾选权限；
2. 在 `系统管理 → 管理员账号` 给账号分配角色；
3. 账号登录后，菜单和按钮按角色显示，未授权操作会被后端拒绝。

**建议的角色划分**：

| 角色 | 建议权限 |
|---|---|
| 超级管理员 | 全部（仅老板/技术负责人持有，日常不要外借） |
| 运营 | 商品、内容、营销、评论、看板 |
| 客服 | 订单查看、发货、售后处理、会员查看 |
| 库管 | 商品查看、库存工作台、批量调库存 |
| 财务 | 订单查看、退款异常、支付异常、日终对账 |

> ⚠️ 超级管理员角色本身不可编辑、不可停用，这是系统的保护机制。

# 第二章 数据看板

菜单：`首页 → 数据看板`

## 2.1 今日经营指标

页面顶部四张指标卡，数据按自然日统计：

| 指标 | 含义 |
|---|---|
| 今日订单 | 今日新创建的订单笔数 |
| 今日实收 | 今日实际收到的支付金额（不含未支付） |
| 今日退款 | 今日成功退出的金额 |
| 今日净销售 | 今日实收扣除今日退款后的净额 |

## 2.2 待处理提醒

当存在「已支付但尚未发货」的订单时，页面会出现醒目提醒：

> 有 N 笔订单待备货发货，请尽快处理

点 **立即处理** 直接跳到订单列表的待发货页签。建议每天开店第一件事就是看这个数字。

## 2.3 趋势与分布

- **订单趋势**：可切换「近 7 天 / 近 30 天」，查看订单量与销售额走势；
- **订单状态分布**：饼图展示各状态占比，用于判断积压环节（如待发货过多）；
- **热销商品 TOP 10**：按销量排序，用于补货与选品参考。

## 2.4 最近订单

表格展示最近订单，含订单号、收货人、商品数、实付金额、退款金额、净入账、订单状态、支付状态、履约状态、下单时间。点订单号可跳到订单详情。

## 2.5 使用建议

- 每天早上：看「待处理提醒」→ 处理待发货；
- 每天中午：看「今日实收 / 今日退款」，异常金额及时查订单；
- 每周一：看 7 天趋势与 TOP 10，安排补货和首页推荐。

# 第三章 商品管理

菜单：`商品管理`

## 3.1 商品列表

菜单：`商品管理 → 商品列表`

### 3.1.1 筛选条件

| 字段 | 说明 |
|---|---|
| 商品名称 | 支持关键词模糊搜索 |
| 分类 | 按分类筛选，含子分类 |
| 状态 | 上架 / 下架 |
| 创建时间 | 起止时间范围 |

### 3.1.2 列表字段

主图、商品名称、分类、售价、市场价、库存、销量、状态、操作。

- **上架**：买家在小程序可以看到并购买；
- **下架**：买家看不到，但数据保留，可随时重新上架。

### 3.1.3 单条操作

| 操作 | 说明 |
|---|---|
| 编辑 | 进入商品表单修改全部内容 |
| 上架 / 下架 | 一键切换售卖状态 |
| 删除 | ⚠️ 软删除，前台不再展示；建议优先用「下架」 |

### 3.1.4 工具栏批量操作

先在左侧勾选商品，再点对应按钮：

| 按钮 | 作用 |
|---|---|
| 新增商品 | 进入商品表单 |
| 打开可视化装修 | 跳到装修预览中心 |
| 下载模板 | 下载商品导入 Excel 模板 |
| 导入商品 | 按模板批量新增或更新 |
| 导出商品 | 导出当前筛选结果为 CSV |
| 批量上架 / 批量下架 | 批量改状态 |
| 批量分类 | 把选中商品统一改到某个分类 |
| 批量排序 | 统一设置排序权重 |
| 批量调价 | 按固定金额或百分比调价，**必须先预览再确认** |
| 批量调库存 | 统一增减库存，必须填写调整原因 |

> 批量调价的规则：先选「固定金额」或「百分比」，输入数值 → 点 **预览** 查看每件商品调前/调后价格 → 预览无失败项后 **确认调价** 才真正生效。

## 3.2 新增商品

菜单：`商品管理 → 商品列表 → 新增商品`

表单分为六个区块，建议从上到下依次填写。

### 3.2.1 基础信息

| 字段 | 必填 | 说明 |
|---|---|---|
| 商品名称 | 是 | 最多 100 字，建议「品类 + 卖点 + 规格」 |
| 商品分类 | 是 | 决定小程序分类页归属 |
| 商品类型 | 是 | 当前版本为「实物商品」 |
| 搜索关键词 | 否 | 建议 3~6 个词，用空格分隔，系统自动保存 |
| 简介 | 否 | 一句话卖点，展示在商品卡片下方 |
| 状态 | 是 | 上架 / 下架，新商品建议先「下架」再核对 |
| 规格模式 | 是 | 单规格（一口价一个库存）/ 多规格（按颜色、规格等组合） |

### 3.2.2 图片设置

| 字段 | 说明 |
|---|---|
| 主图 | 列表与详情首图，从素材库选择或现场上传 |
| 轮播图 | 详情页顶部滑动图，最多 10 张，可拖动排序 |
| 详情图 | 详情页正文图片，保存后按顺序展示 |

图片要求：JPG / PNG / WebP，单张不超过 5MB。建议主图 1:1（如 800×800）。

### 3.2.3 价格与库存

| 字段 | 说明 |
|---|---|
| 售价（元） | 买家实际支付单价 |
| 市场价（元） | 划线价，仅作展示 |
| 库存 | 可售数量 |

- 开启多规格后，售价/市场价/库存由 SKU 表格自动汇总，取最低 SKU 价、库存求和；
- **修改库存必须填写 4~200 字的调整原因**（如「到货入库 100 件」「盘点损耗 2 件」），系统会写入库存流水，便于日后对账。

### 3.2.4 运费设置（重点）

| 字段 | 留空 | 填 0 | 填正数 |
|---|---|---|---|
| 单品运费（元） | 跟随全局运费规则 | 该商品免运费 | 该商品单独按此金额收运费 |
| 单品包邮门槛（元） | 跟随全局包邮门槛 | 该商品始终包邮 | 该商品金额达到此值即包邮 |

规则细节：

1. 全局规则在 `营销管理 → 包邮规则` 维护，例如「满 199 元包邮，否则收 10 元」；
2. 单品设置只覆盖**填写的项**，未填的项继续跟随全局；
3. 单品金额低于单品包邮门槛时收单品运费；达到或超过则免运费；
4. 结算页会按商品逐行计算后汇总，后台「订单详情 → 金额汇总」中的「运费」即为最终结果。

> 想验证是否生效：后台改完保存 → 小程序重新进结算页 → 看运费金额变化。

### 3.2.5 商品详情

- 「详情内容」按普通文字填写即可，不需要写 HTML；
- 建议写：产品卖点、食用/使用场景、适用人群、配料或参数、注意事项；
- 详情图与详情文字会按顺序展示在商品详情页。

### 3.2.6 SKU 规格管理（多规格时）

1. 打开「规格模式 → 多规格」；
2. 添加规格名（如「规格」「口味」）和规格值（如「500g」「1kg」）；
3. 系统自动生成 SKU 组合表；
4. 在表格中逐个填写：价格、SKU 编码、市场价、库存、SKU 图片；
5. 点 **保存**。

> SKU 编码一经使用不建议随意修改，导入更新时靠它匹配商品。

### 3.2.7 保存与预览

- 右侧「实时预览看板」可切换「分类页卡片 / 详情页预览 / 规格价格」，边改边看大致效果；
- 点 **保存** 后立即生效；点 **取消** 放弃本次修改；
- 编辑过程中若库存发生变化，保存时会要求填写调整原因。

## 3.3 编辑商品

菜单：`商品管理 → 商品列表 → 编辑`

可以修改全部字段，重点注意：

1. **改价**：改售价/市场价后保存，小程序立即按新价格结算；
2. **清空运费设置**：把「单品运费 / 单品包邮门槛」清空再保存，才会恢复「跟随全局」；
3. **改库存**：必须在「调整原因」里写清原因，否则无法保存；
4. **改规格**：减少规格值会影响已有 SKU，历史订单不受影响，但库存会重新汇总，操作前建议先导出商品备份。

## 3.4 商品导入与导出

### 3.4.1 导出

`商品列表 → 导出商品`，导出当前筛选结果为 CSV，可用于备份或批量修改前的底稿。

### 3.4.2 导入

1. 点 **下载模板**，得到标准 Excel 模板；
2. 选择导入模式：
   - **新增商品**：适合首次铺货，文件里的 SKU 编码必须是全新的；
   - **更新已有商品**：适合改价、改库存、上下架，建议先导出现有商品，整组修改后再导入；
3. 拖入 Excel / CSV 文件；
4. 点 **预校验**，系统逐行检查并列出「错误列 / 错误原因」；
5. 预校验通过后点 **确认导入**。

> 预校验有错误时不会写入任何数据，按提示修正后重新上传即可。

## 3.5 分类管理

菜单：`商品管理 → 分类管理`

| 字段 | 说明 |
|---|---|
| 上级分类 | 留空为顶级分类，可选某个顶级分类作为父级（支持两级） |
| 分类名称 | 最多 20 字 |
| 分类图标 | 分类页展示的小图标，从素材库选择或上传 |
| 排序权重 | 数值越大越靠前（如 200 排在 100 前） |
| 状态 | 启用 / 禁用，禁用后小程序不展示该分类 |

操作要点：

- 新增、编辑、启用/禁用、删除；
- 分类下有子分类时不允许删除，需先删除子分类；
- 商品所属分类被禁用后，该分类下的商品在分类页不再展示，请同步调整商品分类。

## 3.6 库存工作台

菜单：`商品管理 → 库存工作台`

### 3.6.1 查询

支持按商品名称、SKU 编码/ID、库存状态（正常 / 低库存 / 缺货）筛选，也可勾选「只看低库存」。

### 3.6.2 列表字段

商品、SKU ID、SKU 编码、规格、售价、可售、锁定、当前库存、预警库存、状态。

- **可售** = 当前库存 − 锁定（未发货订单占用）；
- **锁定** = 已支付未发货订单占用的数量。

### 3.6.3 操作

| 操作 | 说明 |
|---|---|
| 调库存 | 输入调整数量（正数增加、负数减少）+ 4~200 字原因，提交后写入流水 |
| 预警 | 设置该 SKU 的低库存预警值，低于该值状态变「低库存」 |
| 流水 | 查看该 SKU 的全部库存变动记录，可按业务单号搜索 |
| 库存对账 | 对比「当前库存」与「流水累计库存」，列出差异 SKU |

> 「库存对账」出现差异时不要直接改数，先看流水定位原因（如手工改库、并发扣减），再决定是否调整。

## 3.7 素材库

菜单：`商品管理 → 素材库`

### 3.7.1 上传

1. 选择业务类型：**商品素材 / 内容素材 / 通用素材**；
2. 点 **上传图片**，支持 JPG / PNG / WebP，单张 ≤ 5MB；
3. 上传成功后可在商品、Banner、频道、品牌、专题、店铺 Logo 等处直接选用。

### 3.7.2 管理

- 按业务类型、关键词（文件名或 URL）、上传人、上传时间筛选；
- 每个素材显示尺寸、大小、**引用数**；
- 可复制图片 URL、查看引用位置；
- ⚠️ 删除前请确认「引用数」为 0，或已替换所有引用位置，否则前台会出现裂图。

## 3.8 评论管理

菜单：`商品管理 → 评论管理`

| 操作 | 说明 |
|---|---|
| 详情 | 查看评论内容、用户、商品、时间 |
| 审核通过 | 评论变为「显示」，前台展示 |
| 隐藏 | 评论变为「隐藏」，前台不再展示（不删除数据） |

可按状态（显示 / 隐藏）筛选。建议每天处理一次：差评先联系客户，再决定是否隐藏；正常好评及时通过。

# 第四章 交易管理

菜单：`交易管理`

## 4.1 订单管理

菜单：`交易管理 → 订单管理`

### 4.1.1 页签

`全部 / 待发货 / 待收货 / 已完成 / 已取消 / 退款中`

> 未支付订单不在独立页签中，请在「全部」页签下用「支付状态 = 未支付」筛选。

### 4.1.2 筛选条件

订单号（完整）、用户 ID、手机号前缀、支付状态（未支付 / 已支付 / 已退款）、下单时间范围。

### 4.1.3 列表与批量工具

列表字段：订单号、用户信息、商品摘要、实付金额、状态、履约进度、下单时间。

批量工具：

| 按钮 | 说明 |
|---|---|
| 导出 | 导出当前筛选结果为 CSV |
| 批量发货 | 下载 CSV 模板 → 填写 → 预校验 → 确认导入发货 |
| 打印拣货单 | 勾选多个订单后一次打印，用于仓库拣货 |

### 4.1.4 订单详情

点订单号或 **详情** 打开右侧抽屉，包含：

1. **基础信息**：订单状态、履约进度、用户 ID、下单时间、支付时间、关闭时间/原因；
2. **收货信息**：收货人、手机号、完整地址；
3. **商品明细**：商品、规格、单价、数量、小计；
4. **金额汇总**：商品金额、运费、优惠、实付金额；
5. **支付信息**：支付单号、支付渠道、支付状态、支付金额、支付时间；
6. **内部备注**：仅后台可见，不会展示给买家，修改后点 **保存备注**；
7. **订单状态时间线**：记录下单、支付、发货、售后等关键动作与操作人。

### 4.1.5 发货

两种入口：

- 列表操作列 → **发货**；
- 订单详情 → 右上角 **发货**（或变更履约状态时选「已发货」）。

必填：

| 字段 | 规则 |
|---|---|
| 物流公司 | 下拉选择（顺丰、中通、圆通、韵达、京东、邮政等） |
| 物流单号 | 6~32 位字母、数字或连字符，只支持英文状态下的字符 |

发货成功后：订单状态变为「待收货」，履约状态变为「已发货」，买家可在小程序查看物流。

### 4.1.6 变更履约状态

入口：订单详情 → 右上角 **变更履约状态**。

| 履约状态 | 使用场景 | 是否必须填单号 |
|---|---|---|
| 待备货 | 刚支付，仓库尚未开始处理 | 否 |
| 备货中 | 仓库正在打包 | 否 |
| 待揽收 | 已打包，等待快递取件 | 否 |
| 已发货 | 快递已取件/已交寄 | **是**，必须选择物流公司并填写单号 |
| 已签收 | 买家已收货 | 否 |
| 物流异常 | 丢件、破损、地址异常等 | 否 |

说明：

- 履约状态是给商家内部和买家查看的**进度标记**，与订单主状态（待发货/待收货/已完成）配合使用；
- 改为「已发货」时若未填单号，系统会直接拦截并提示；
- 变更为其他状态可填写备注，方便客服交接。

### 4.1.7 物流查询

列表操作列 → **物流**：显示物流公司、单号、发货时间与完整轨迹。轨迹为空时会提示原因（如快递公司未返回数据）。

### 4.1.8 批量发货

1. 点 **批量发货** → **下载模板**；
2. 按模板填写订单号、物流公司编码、物流单号；
3. 选择 CSV 文件 → **预校验**（只检查不写入）；
4. 确认无误 → **确认导入发货**；
5. 结果表按行显示「成功 / 失败 + 说明」，失败行修正后重新导入即可。

### 4.1.9 打印

- **发货单**：在订单详情或列表打印单笔发货单，含收货信息、商品、金额、备注；
- **拣货单**：勾选多笔订单后打印，按商品汇总应拣数量，适合仓库配货。

## 4.2 售后管理

菜单：`交易管理 → 售后管理`

### 4.2.1 售后类型

| 类型 | 适用场景 | 处理路径 |
|---|---|---|
| 仅退款 | 未发货，或买家不退货只退款 | 同意 → 立即退款 |
| 退货退款 | 已发货，需要买家寄回 | 同意 → 等买家寄回 → 商家确认收货 → 退款 |

### 4.2.2 状态说明

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| 待审核 | 买家刚提交申请 | 核对订单与理由，选择同意或拒绝 |
| 待买家寄回 | 退货退款已同意，等买家填单号 | 等待，超时未寄回可联系买家 |
| 待商家收货 | 买家已填退货单号 | 收到货后点「确认收货」并发起退款 |
| 退款处理中 | 已向微信支付发起退款 | 等待结果，失败时到「退款异常」处理 |
| 退款失败 | 渠道返回失败，需人工介入 | 到「退款异常」看原因并重试/人工处理 |
| 已退款 | 退款成功 | 无需操作，可核对金额 |
| 已拒绝 | 已驳回申请 | 查看拒绝原因，必要时与买家沟通 |
| 已撤销 | 买家主动撤销 | 无需操作 |

### 4.2.3 同意 / 拒绝

在「待审核」页签找到申请：

- **同意**：
  - 仅退款：弹窗确认退款金额 → 立即发起退款；
  - 退货退款：弹窗提示「通过后等待买家寄回，收货前不会退款」→ 进入「待买家寄回」；
- **拒绝**：必须填写 4~200 字拒绝原因，该原因会展示给买家。

### 4.2.4 确认收货并退款

买家填了退货单号、状态变为「待商家收货」后：

1. 核对实际收到的退货；
2. 点 **确认收货** → 弹窗确认退款金额；
3. 系统发起退款，状态进入「退款处理中」，成功后变「已退款」。

> 确认收货会同时恢复库存、回滚销量；如未收到货请勿点确认。

### 4.2.5 同步退款状态

「退款处理中」的申请可点 **同步** 主动查询渠道结果，适合自动重试未及时成功的场景。

## 4.3 退款异常

菜单：`交易管理 → 退款异常`

用于集中处理退款失败或超时未完成的单。

### 4.3.1 筛选

退款单号、售后单号、订单号、退款状态（退款处理中 / 退款失败 / 已退款）、列表范围（仅异常 / 全部退款）、时间范围。

### 4.3.2 操作

| 操作 | 说明 |
|---|---|
| 详情 | 查看退款单、支付单、异常编码与说明、任务记录、回调记录 |
| 同步 | 向渠道查询最新状态并落库 |
| 重试 | 重新提交退款任务（状态为处理中/失败时可用） |
| 处理 | 人工标记异常已处理，需填写处理备注（仅在已线下解决时使用） |

### 4.3.3 常见异常

| 异常编码/提示 | 原因 | 处理建议 |
|---|---|---|
| NOT_ENOUGH | 商户号可用余额不足（当天收款未结算最常见） | 等 T+1 结算或给商户号充值后点「同步/重试」 |
| ORDER_NOT_EXIST / RESOURCE_NOT_EXISTS | 微信侧查不到该笔交易（多为测试模拟支付） | 确认是否真实支付单；测试单走「处理」标记 |
| PARAM_ERROR | 退款金额或参数不合法 | 核对退款金额是否超过实付 |
| 签名/证书类错误 | 商户证书或序列号配置错误 | 联系技术负责人检查支付配置 |

> ⚠️ 「处理」只是后台标记，不会真的退钱。只有微信侧退款成功，买家的钱才会原路退回。

## 4.4 支付异常

菜单：`交易管理 → 支付异常`

分两个页签：

1. **异常列表**：系统巡检发现的支付不一致，如
   - 微信已支付本地未支付；
   - 本地关闭微信已支付；
   - 支付中超时；
   - 回调验签失败；
   - 金额不一致；
   - 查单失败。
2. **支付单**：按支付单号/订单号/支付状态查询全部支付单。

操作：

- **同步**：主动向微信查单并更新本地状态；
- **处理**：标记异常已处理并填写备注（确认已人工核对或已线下解决）。

联动：支付异常修复后，对应的订单状态与履约状态会在订单列表中同步更新。

## 4.5 日终对账

菜单：`交易管理 → 日终对账`

### 4.5.1 生成对账

1. 选择「对账日期」（一般选昨天）；
2. 点 **生成对账**；
3. 系统汇总本地支付/退款数据，并与微信账单比对，生成对账批次。

### 4.5.2 对账列表

字段：对账日期、状态（处理中 / 完成 / 失败）、本地支付笔数与金额、本地退款笔数与金额、本地净收入、差异笔数、来源、说明。

### 4.5.3 差异处理

点批次 **详情** 可查看：

- 汇总：本地支付/退款/净收入、微信支付/退款/净收入、手续费、交易账单与资金账单；
- 差异明细：差异类型、业务单号、订单号、本地金额与渠道金额、本地状态与渠道状态、原因。

对每条差异确认后可点 **处理** 标记完成。常见差异原因：支付成功但回调延迟、退款到账时间差、渠道手续费四舍五入。

> 建议每天上午对前一天做一次对账，差异当天清零；连续差异必须联系技术排查。

## 4.6 运行监控

菜单：`交易管理 → 运行监控`

三个区块：

1. **当前告警**：级别、标题、说明、当前值/阈值、触发次数、最近触发时间；
2. **定时任务**：任务名、状态、处理数、成功/失败数、连续失败次数、最近执行与说明；
3. **订单链路追踪**：输入订单号 → **追踪**，查看订单/支付/售后/退款全链路事件与时间线。

用途：客户反馈「付了钱订单没变」「退款没到账」时，先用订单号追踪一次，能快速判断卡在支付、发货还是退款环节。

# 第五章 营销管理

## 5.1 优惠券管理

菜单：`营销管理 → 优惠券管理`

### 5.1.1 新建优惠券

| 字段 | 说明 |
|---|---|
| 券名称 | 最多 30 字，如「满 100 减 20」 |
| 券类型 | 满减券 / 新人券 |

## 5.2 满减活动

菜单：`营销管理 → 满减活动`

| 字段 | 说明 |
|---|---|
| 活动名称 | 如「满 200 减 30」 |
| 满减门槛（元） | 必须大于 0 |
| 优惠金额（元） | 必须大于 0，且不能大于门槛 |
| 优先级 | 数值越大越优先匹配（同一订单只取最优/最高优先级规则） |
| 开始、结束时间 | 留空表示不限 |
| 状态 | 启用 / 禁用 |

可编辑、删除、启用/禁用。活动叠加顺序以系统规则为准，配置前建议小额下单验证一次。

## 5.3 包邮规则

菜单：`营销管理 → 包邮规则`

### 5.3.1 规则字段

| 字段 | 说明 |
|---|---|
| 规则名称 | 至少 2 字 |
| 基础运费（元） | 未达包邮门槛时收取的运费；填 0 表示全场包邮 |
| 免邮门槛（元） | 订单金额达到该值免运费 |
| 生效时间 / 停用时间 | 留空表示立即生效 / 长期有效 |
| 状态 | 启用 / 停用 |

### 5.3.2 生效逻辑

1. 同一时间只有一条规则「生效中」（按生效时间与 ID 取最新）；
2. 下单时按商品逐行计算：商品金额 ≥ 免邮门槛则 0 元，否则收基础运费，最后汇总；
3. 商品若在 `商品管理 → 编辑商品 → 运费设置` 中填了单品运费或单品门槛，则该商品优先使用单品设置；
4. 停止时间必须晚于生效时间。

### 5.3.3 变更记录

点 **变更记录** 可查看规则的修改历史（操作人、接口、结果、说明），用于追溯谁在什么时候改了运费。

> 改完运费后请立即到小程序验证一单：结算页运费是否按新规则计算。

可切换页签：**首页预览 / 商品详情预览**。

菜单：`系统管理 → 新订单通知`

| 授权码 | 邮箱后台生成的 SMTP 授权码，**不是登录密码** |
| 发件人地址 | 留空则默认使用登录账号 |
| 连接方式 | SSL 直连（465）/ STARTTLS（587） |

### 8.2.3 测试与记录

1. 先点 **保存设置**；
2. 再点 **发送测试邮件**（测试使用已保存的配置）；
3. 到收件箱确认收到测试邮件；
4. 下方「最近推送记录」可查看每笔订单的通知结果（订单号、渠道、接收方、成功/失败、说明、发送时间）。

常见失败原因：授权码填成了登录密码、端口与连接方式不匹配、邮箱未开启 SMTP 服务、收件人地址拼写错误。

## 8.3 管理员账号

菜单：`系统管理 → 管理员账号`

### 8.3.1 新增管理员

| 字段 | 说明 |
|---|---|
| 账号 | 登录名，创建后不可修改 |
| 初始密码 | 至少 10 位，含字母和数字 |
| 姓名 | 显示名称 |
| 头像地址 | 可选，HTTPS 地址或站内资源 |
| 角色 | 可多选，决定菜单与操作权限 |

### 8.3.2 账号操作

| 操作 | 说明 |
|---|---|
| 编辑 | 改姓名、头像、角色；保存后该账号会话失效，需重新登录 |
| 停用 / 启用 | 停用后立即注销该账号全部会话，无法登录 |
| 解锁 | 清除连续登录失败计数，解除临时锁定 |
| 重置密码 | 设置新密码，原会话失效 |
| 强制注销 | 让该账号当前所有登录状态立即失效 |

> 建议：一人一号，不共用超级管理员；离职当天停用账号。

## 8.4 角色权限

菜单：`系统管理 → 角色权限`

### 8.4.1 字段

| 字段 | 说明 |
|---|---|
| 角色编码 | 如 `ORDER_OPERATOR`，创建后不可修改 |
| 角色名称 | 如「订单客服」 |
| 接口权限 | 按分组勾选，勾选项展示「权限名 + 方法 + 接口路径」 |

### 8.4.2 规则

- 新增角色 → 勾选权限 → 保存；
- 编辑角色权限后，相关账号会话失效，需重新登录；
- 停用角色后，关联账号立即失去该角色权限；
- 超级管理员角色不可编辑、不可停用。

> 权限是「接口级」的：只给菜单权限而没有对应接口权限，页面可能打开但按钮报「无权限」。建议按角色模板整体勾选。

## 8.5 审计日志

菜单：`系统管理 → 审计日志`

两个页签：

1. **操作日志**：时间、操作人、风险级别（高风险/普通）、操作类型、方法、接口路径、业务编号、结果、耗时、说明；展开行可看角色快照、变更前、变更后；
2. **登录日志**：时间、账号、姓名、IP、结果、说明、客户端（User-Agent）。

用途：

- 发现价格/库存/权限被改动时，按业务编号或接口路径定位操作人；
- 排查异地登录、暴力破解（登录日志失败记录 + IP）。

建议每月导出或截图留存一次高风险操作日志。

# 第九章 日常运营标准流程

## 9.1 每天开店（9:00 前）

1. 打开 `首页 → 数据看板`，看待处理提醒与昨日数据；
2. `交易管理 → 订单管理 → 待发货`，处理新订单并填物流单号；
3. `交易管理 → 售后管理 → 待审核`，当天申请当天处理；
4. `交易管理 → 退款异常`，清掉前一天失败退款；
5. `商品管理 → 库存工作台 → 只看低库存`，安排补货。

## 9.2 每天闭店（18:00 前）

1. 确认待发货清零（或已与客户沟通延迟）；
2. 处理完「待商家收货」的退货；
3. `内容管理 → 用户反馈` 处理完待处理反馈；
4. 检查新订单通知是否正常（最近推送记录无连续失败）。

## 9.3 每周

1. 数据看板：7 天趋势、热销 TOP 10；
2. 商品：下架滞销品、补充新品、核对价格；
3. 营销：检查优惠券/满减活动是否到期；
4. 评论：集中审核与回复。

## 9.4 每月

1. 日终对账逐日复核，确认无未处理差异；
2. 管理员账号盘点（离职账号停用、权限复核）；
3. 导出商品与订单数据留档；
4. 审计日志抽查高风险操作。

## 9.5 大促前

1. 提前 3 天完成商品价格、库存、主图与详情检查；
2. 配置优惠券、满减、包邮规则，并小额下单验证叠加结果；
3. 首页 Banner、频道、专题提前上线并预览；
4. 确认新订单通知收件人包含仓库与客服；
5. 大促当天安排专人盯「待发货」与「退款异常」。

# 第十章 常见问题（FAQ）

### Q1：后台改了商品，小程序看不到？

按顺序排查：

1. 商品状态是否为「上架」；
2. 商品分类是否被禁用；
3. 小程序是否停留在旧页面，杀掉小程序重新进入；
4. 是否改的是草稿预览而没点「保存」。

### Q2：运费没有按设置收？

1. `营销管理 → 包邮规则` 是否有「生效中」的规则；
2. 商品是否填了单品运费/门槛（单品优先于全局）；
3. 商品金额是否已达到包邮门槛；
4. 改完规则后，结算页需重新进入才会重新计算。

### Q3：买家申请退款，后台在哪里处理？

`交易管理 → 售后管理 → 待审核`，点 **同意**。仅退款会立即发起退款；退货退款需等买家寄回后点 **确认收货**。

### Q4：退款一直显示「退款处理中」或失败？

到 `交易管理 → 退款异常` 查看异常编码：

- `NOT_ENOUGH`：商户号余额不足（当天收款未结算最常见），等结算或充值后点 **同步/重试**；
- 其他编码：把异常说明发给技术负责人；
- ⚠️ 不要用「处理」代替真实退款，否则会出现「后台显示已处理、客户没收到钱」。

### Q5：收不到新订单邮件？

1. `系统管理 → 新订单通知` 是否开启；
2. 收件人邮箱是否用英文逗号分隔；
3. 先保存再点「发送测试邮件」；
4. 检查授权码、端口与连接方式；
5. 查看「最近推送记录」中的失败说明。

### Q6：账号被锁定/忘记密码？

- 锁定：让超级管理员到 `系统管理 → 管理员账号` 点 **解锁**；
- 忘记密码：让超级管理员点 **重置密码**，登录后自行修改。

### Q7：为什么看不到某个菜单？

当前账号的角色没有该菜单权限，联系超级管理员在 `系统管理 → 角色权限` 授权，重新登录后生效。

### Q8：批量导入商品失败？

先点 **预校验**，按「错误列 / 错误原因」修正：

- SKU 编码重复 → 换新编码或改用「更新已有商品」模式；
- 分类不存在 → 先在分类管理建好；
- 数字列填了文字 → 改为纯数字。

### Q9：删除素材后前台图片裂了？

素材被引用时不能直接删除。先到素材详情看「引用数」与引用位置，替换后再删。

### Q10：改了店铺名称，小程序没变？

`系统管理 → 店铺展示设置` 只改小程序内展示名；微信小程序账号名称需到微信公众平台修改，且需要审核。

### Q11：订单显示「物流异常」，会不会影响退款？

不影响。履约状态只是进度标记，售后与退款按独立流程走。

### Q12：误改了价格/库存，怎么恢复？

1. 价格：用批量调价或单商品编辑改回，审计日志可查改前值；
2. 库存：用库存工作台「调库存」并填写原因，流水可追溯；
3. 内容：可视化装修支持「一键回退」到最近一次修改前状态。

# 附录 D 使用建议与支持

## D.1 浏览器与设备

- 推荐 Chrome / Edge 最新版，分辨率 ≥ 1366×768；
- 不建议用手机浏览器操作后台（表格与批量功能体验较差）。

## D.2 安全建议

1. 一人一号，禁止共用超管账号；
2. 密码 ≥ 10 位且含字母与数字，每季度更换；
3. 离职当天停用账号并强制注销；
4. 高风险操作（改价、调库存、改权限）前先确认，事后可在审计日志追溯；
5. 后台地址、账号密码不要发在群聊或截图里。

## D.3 遇到问题时提供给技术的信息

1. 页面路径（如 `交易管理 → 售后管理`）；
2. 订单号 / 售后单号 / 商品 ID；
3. 操作时间与当前账号；
4. 页面报错原文或截图；
5. 若涉及退款，附「退款异常」中的异常编码与说明。
