# v1.0 本地执行验收报告（2026-08-17）

> 本报告记录 2026-08-17 在本地开发环境实际执行的验收结果。它不是客户最终签署报告，也不替代生产环境、微信真机、真实支付退款、快递 100 和灾备演练证据。

## 1. 验收结论

**本轮结论：有条件通过本地技术验收，不具备正式交付签署条件。**

- 已通过：本地管理员登录与稳定跳转、首页数据看板加载、后端健康运行、管理后台类型检查与生产构建、数据库迁移重放、Mock 交易闭环及本地静态交付门禁。
- 部分通过：管理后台商品新增、上下架、素材上传、商品导入和导出提示已实操；其余内容管理、发货、退款、对账和权限越权操作尚未逐项留证。
- 已修复：Windows PowerShell 5 中文脚本解析、历史内容乱码、3 组失效图片地址，以及本地素材匿名访问和容器重启后丢失问题均已修复并复验。
- 需要人力验收：小程序 UI 与真机交互、正式 HTTPS 域名、客户 AppID 与合法域名、真实微信支付退款、真实快递 100、生产备份恢复与回滚、生产 Secret/依赖漏洞审计、客户签字。

## 2. 状态定义与验收边界

| 状态 | 定义 |
|------|------|
| 通过 | 本轮已实际执行，结果与通过标准一致，并有命令输出或页面状态作为证据 |
| 部分通过 | 仅验证了入口、页面加载、接口能力或部分链路，不能覆盖完整业务操作 |
| 未通过 | 已执行但报错、结果不符合标准，或验收工具本身无法可靠运行 |
| 需要人力验收 | 依赖真机、客户账号、生产环境、真实资金/物流、视觉判断或签字，不能由本地代码检查替代 |

自动化测试只能证明其覆盖范围内的接口与规则；不能据此认定页面视觉、真实微信渠道、真实物流、生产安全和客户体验已经通过。

### 管理后台本轮发现的问题

1. Windows PowerShell 5 会把 UTF-8 无 BOM 的中文脚本按本地代码页解析，曾导致多项静态门禁报语法错误；现已为受影响脚本补充 UTF-8 BOM，并逐项复验通过。
2. `scripts/verify-production-config.ps1` 本轮退出 0，但它只能证明脚本覆盖的配置文本检查，不代表真实生产环境已经部署或关闭全部 Mock。
3. 本地列表中发现的 `????` 已确认是少量早期演示脏数据，已由 `V20260817_01` 增量迁移定向修复。
4. 直接连续切换多个后台路由时，部分页面正文短时间保留上一页面板；本轮未将这类短暂状态视为对应功能通过。应由人工以正常菜单操作复验页面最终内容。
5. 素材上传初次实操发现 `/uploads/material/**` 被统一鉴权拦截，匿名访问返回 401；已放行该静态路径，复验返回 `200 image/png`。
6. 本地 Docker 初始未挂载素材目录，重建后已上传文件丢失；已增加 `/app/material` 持久卷和 `MATERIAL_STORAGE_ROOT`，后端容器重启前后均返回同一文件且状态为 200。
7. 商品导出页面已显示“商品导出完成”且无控制台错误，但导出采用 Blob/ObjectURL，浏览器控制未捕获到下载文件；因此只认定导出触发成功，文件内容仍保留为人力验收。
