# v1.0 微信支付退款验收记录

> 本文用于客户正式商户资料到位后的实单验收归档。代码侧已具备支付回调、主动查单、关单、退款发起、退款回调、退款同步、异常工作台、运行监控和幂等审计能力；真实验收必须使用客户正式 AppID 与商户号执行。

## 1. 客户资料

| 项目 | 要求 | 结果 |
|------|------|------|
| 微信小程序 AppID | 与商户支付 AppID 一致 | 待客户提供 |
| 微信小程序 AppSecret | 写入生产/预发布环境变量 | 待客户提供 |
| 微信支付商户号 | `WECHAT_PAY_MCH_ID` | 待客户提供 |
| 商户 API 证书私钥 | `WECHAT_PAY_PRIVATE_KEY_PATH` 指向服务器本地安全路径 | 待客户提供 |
| API v3 Key | `WECHAT_PAY_API_V3_KEY`，32 字节 | 待客户提供 |
| 微信支付平台证书 | `WECHAT_PAY_PLATFORM_CERTIFICATE_PATH` | 待客户提供 |
| 支付回调地址 | `WECHAT_PAY_NOTIFY_URL`，必须 HTTPS | 待客户提供 |
| 退款回调地址 | `WECHAT_PAY_REFUND_NOTIFY_URL`，必须 HTTPS | 待客户提供 |

## 2. 环境变量

生产和预发布环境必须配置：

```text
WECHAT_PAY_ENABLED=true
WECHAT_PAY_APP_ID=<客户小程序 AppID>
WECHAT_PAY_MCH_ID=<客户微信支付商户号>
WECHAT_PAY_MERCHANT_SERIAL_NO=<商户 API 证书序列号>
WECHAT_PAY_PRIVATE_KEY_PATH=<服务器上的商户私钥路径>
WECHAT_PAY_API_V3_KEY=<32字节 API v3 Key>
WECHAT_PAY_PLATFORM_CERTIFICATE_PATH=<服务器上的微信支付平台证书路径>
WECHAT_PAY_NOTIFY_URL=https://<客户域名>/app-api/pay/wechat/notify
WECHAT_PAY_REFUND_NOTIFY_URL=https://<客户域名>/app-api/pay/wechat/refund-notify
TRADE_REFUND_PROVIDER=wechat
```

## 3. 验收用例

| 编号 | 用例 | 操作 | 通过标准 | 证据 |
|------|------|------|----------|------|
| PAY-01 | 真实小额订单支付成功 | 小程序提交 0.01 元或客户认可的小额订单并支付 | 小程序返回支付成功，后台订单为待发货或对应已支付状态 | 订单号、支付单号、截图 |
| PAY-02 | 支付回调验签成功 | 支付成功后等待微信回调 | `pay_notify_log` 有 `status=1` 记录，运行监控无支付回调失败告警 | 通知 ID、日志截图 |
| PAY-03 | 重复支付回调幂等 | 使用同一微信通知重放或等待微信重试 | 订单和支付单不重复变更，通知流水保持单次处理 | SQL 截图 |
| PAY-04 | 主动查单状态正确 | 后台或定时任务同步支付单 | 微信返回 `SUCCESS` 时本地状态与金额一致 | 查询日志 |
| PAY-05 | 取消未支付订单关单成功 | 创建未支付订单后取消 | 本地订单关闭，微信关单接口无未处理异常 | 订单号、接口日志 |
| REFUND-01 | 仅退款成功 | 对未发货已支付订单申请仅退款并审核通过 | 售后单为已退款，支付单退款金额正确，库存恢复正确 | 售后单号、退款单号 |
| REFUND-02 | 退货退款成功 | 发货后申请退货退款，填写退货单并后台收货后退款 | 售后单为已退款，订单退款状态正确 | 售后截图、物流截图 |
| REFUND-03 | 退款处理中可同步 | 微信返回 `PROCESSING` 时执行人工同步 | 售后单保持退款处理中，并记录下次同步时间 | 退款详情截图 |
| REFUND-04 | 退款失败进入异常工作台 | 微信返回 `ABNORMAL` 或 `CLOSED` | 售后单为退款失败，退款异常工作台出现未处理记录 | 异常详情截图 |
| REFUND-05 | 退款重复通知幂等 | 同一退款通知重复到达 | `refund_notify_log.notification_id` 唯一，订单/支付单退款金额不重复累计 | 通知流水截图 |

## 4. 数据库核对 SQL

```sql
SELECT notification_id, pay_sn, channel_trade_no, event_type, status, message, create_time
  FROM pay_notify_log
 WHERE pay_sn = '<支付单号>'
 ORDER BY id DESC;

SELECT notification_id, after_sale_sn, provider_refund_no, pay_sn,
       event_type, refund_status, refund_amount, status, message, create_time
  FROM refund_notify_log
 WHERE after_sale_sn = '<售后单号>'
 ORDER BY id DESC;

SELECT id, after_sale_sn, status, refund_amount, refund_channel_state,
       refund_exception_code, refund_exception_message, refund_handled
  FROM trade_after_sale
 WHERE after_sale_sn = '<售后单号>';
```

## 5. 失败归档

如验收失败，需要归档以下信息：

- 订单号、支付单号、售后单号、微信交易号、微信退款单号。
- 后台运行监控的订单链路追踪截图。
- `pay_notify_failure_log` 或 `refund_notify_failure_log` 对应记录。
- 微信商户平台交易详情或退款详情截图。
- 修复结论与复测结果。
