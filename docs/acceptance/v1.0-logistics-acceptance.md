# v1.0 真实物流验收记录

> 本文用于客户快递 100 正式账号和真实物流单号到位后的验收归档。代码侧已具备快递 100 查询、物流公司编码校验、后台发货、小程序轨迹展示、后台轨迹展示、查询失败提示和 30 分钟缓存能力。

## 1. 客户资料

| 项目 | 要求 | 结果 |
|------|------|------|
| 快递 100 customer | `KUAIDI100_CUSTOMER` | 待客户提供 |
| 快递 100 key | `KUAIDI100_KEY` | 待客户提供 |
| 常用物流公司列表 | 需映射为快递 100 公司编码 | 待客户确认 |
| 真实可查询物流单号 | 至少 1 个，需包含物流公司、单号、收件人手机号 | 待客户提供 |

## 3. 环境变量

生产和预发布环境必须配置：

```text
TRADE_LOGISTICS_PROVIDER=kuaidi100
KUAIDI100_CUSTOMER=<客户快递100 customer>
KUAIDI100_KEY=<客户快递100 key>
```

## 4. 验收用例

| 编号 | 用例 | 操作 | 通过标准 | 证据 |
|------|------|------|----------|------|
| LOG-01 | 后台发货公司编码校验 | 后台选择物流公司并填写单号发货 | 公司名与编码一致才能提交，不一致会拒绝 | 后台发货截图 |
| LOG-02 | 真实物流单号可查询 | 使用客户真实单号查询 | 后端返回真实轨迹，`queryMessage=查询成功` | 接口响应或后台截图 |
| LOG-03 | 小程序订单详情展示轨迹 | 小程序打开已发货订单详情 | 显示物流公司、单号、发货时间和轨迹列表 | iOS/Android 截图 |
| LOG-04 | 后台订单详情展示轨迹 | 后台订单列表点击查看物流 | 展示轨迹时间线 | 后台截图 |
| LOG-05 | 查询失败不影响订单详情 | 临时使用错误单号或断开快递 100 | 页面仍展示订单与发货信息，并提示物流暂不可用 | 页面截图 |
| LOG-06 | 查询失败回退缓存 | 先成功查询，再让供应商不可用后查询 | 页面展示最近缓存，并提示“当前显示最近缓存” | 两次查询截图 |
| LOG-07 | 缓存策略生效 | 30 分钟内重复查看物流 | 不重复请求供应商，直接使用本地缓存 | 日志或数据库截图 |

## 5. 数据库核对 SQL

```sql
SELECT order_id, logistics_company, logistics_code, logistics_no,
       delivery_time, last_query_time, query_message, traces_json
  FROM trade_order_logistics
 WHERE order_id = <订单ID>
 ORDER BY id DESC
 LIMIT 1;
```

## 6. 失败归档

如验收失败，需要归档以下信息：

- 订单号、物流公司、物流编码、物流单号、收件手机号后四位。
- 后台物流详情截图与小程序订单详情截图。
- `trade_order_logistics.query_message` 与 `last_query_time`。
- 快递 100 控制台查询结果或错误截图。
- 修复结论与复测结果。
