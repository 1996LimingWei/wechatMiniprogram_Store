# 交易演示数据与可替换 Provider 实施计划

## 目标

在当前订单与售后管理功能上补齐可重复演示数据、退款与物流 Provider 边界，并修复售后分页和审批定位问题，为后续真实数据与第三方能力替换做好准备。

## 实施步骤

1. 定义退款 Provider、物流 Provider 及配置选择服务。
2. 实现开发环境 Mock Provider 与生产安全的 Disabled Provider。
3. 售后单增加退款 Provider 信息及“退款处理中”状态，审批改用售后单 ID。
4. 售后列表改为 MyBatis-Plus 数据库分页，后端强制校验拒绝原因。
5. 物流详情改由 Provider 返回轨迹，订单列表不触发外部物流查询。
6. 新增可重复执行的订单、支付、物流、售后与日志演示数据脚本及使用说明。
7. 增加 Provider 契约、售后审批、数据库分页和物流查询测试。
8. 执行后端测试、管理后台检查与构建，并更新项目状态。

## 验收标准

1. 开发环境使用 Mock Provider，可完成发货、查看物流、同意退款与拒绝退款。
2. 生产环境未配置真实 Provider 时不会伪造退款成功或物流轨迹。
3. 演示脚本重复执行结果一致，并且不修改演示 ID 区间之外的数据。
4. 售后列表使用数据库分页，审批请求使用 `afterSaleId`。
5. 后端测试、管理后台 ESLint、类型检查和生产构建全部通过。
