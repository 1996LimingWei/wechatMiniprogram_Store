# v1.0 客户交付版技术与实施方案

## 1. 版本目标

`v1.0 客户交付版` 的目标不是继续做演示能力，而是完成可交付客户上线试运营的最小生产版本。

本版本完成后必须达到：

- 客户运营人员可以在管理后台独立维护商品、图片、库存、运费、订单、发货、售后和资金异常。
- 用户可以在小程序完成登录、浏览、加购、下单、支付、查看物流、申请售后、查看退款状态。
- 系统可以接入客户真实微信小程序、微信支付、微信退款、快递 100 和正式域名。
- 生产环境可以部署、回滚、备份、监控、排障。
- CI 能阻止编译失败、类型错误、数据库迁移失败、API 契约漂移和敏感配置误提交。
- 有完整部署文档、运维文档、验收清单和客户交付资料。

## 2. 交付边界

### 2.1 本版必须包含

- 单商户商城。
- 单库存池。
- 整单单包裹发货。
- 微信小程序端。
- 管理后台。
- 商品、分类、素材、库存、订单、物流、售后、支付、退款、对账。
- 优惠券、满减、包邮规则的基础运营能力。
- 管理员账号、角色权限、登录日志、操作日志。
- 生产部署、健康检查、备份恢复、发布回滚。
- 微信支付、退款、快递 100 的真实小额验收。

### 2.2 本版明确不包含

以下能力不进入 v1.0，避免交付范围无限扩张：

- 付费会员、会员等级、会员价、会员折扣。
- 分销、积分、拼团、秒杀、直播。
- 多商户。
- 多仓库。
- 拆单多包裹。
- WMS/ERP 对接。
- 采购、供应商、入库单。
- 发票。
- 财务总账。
- CRM。
- 报表大屏。
- 复杂区域运费模板，除非客户上线前明确必须。

如客户要求上述能力，必须另开 v1.1 或独立项目范围，不阻塞 v1.0 交付。

- 企业交付阶段 B 已完成：管理员账号、角色权限、前端菜单和按钮权限、登录日志、操作审计中心。

- 远端已合入营销模块：优惠券、满减、包邮规则已有基础后端、后台和小程序能力。

## 4. v1.0 总体验收口径

只有以下条件全部满足，才允许标记 v1.0 可交付：

- [x] 不依赖开发人员手写图片 URL 即可创建并上架商品。
- [x] 客户可以批量导入、导出、上架、下架、调价、调库存。
- [x] 库存变化有流水，可按 SKU、业务单号、时间追溯。
- [x] 结算、下单和订单详情的运费、优惠、实付金额一致。
- [ ] 真实微信支付成功，回调成功，主动查单成功。
- [ ] 真实微信退款成功，退款回调或主动同步成功。
- [ ] 快递 100 正式物流轨迹可查询。
- [ ] 支付异常、退款异常、对账差异可以在后台处理，不需要查数据库。
- [ ] 管理员权限矩阵清晰，高风险操作全部审计。
- [ ] 后端、管理后台、小程序、数据库迁移、交易流、对账脚本可自动验证。
- [ ] 生产环境配置不使用默认密码、不使用 Mock 支付退款、不暴露测试入口。
- [ ] 部署、回滚、备份、恢复、监控、告警、验收文档齐全。
- [ ] 微信体验版通过真机回归，提审资料齐全。

## 16. P0-12 角色权限矩阵复核

### v1.0 标准角色

- [ ] 每个管理后台菜单都有权限码。
