# 微信小程序生产就绪实施计划

## 1. 当前判断

当前代码是“高保真页面 + 交易 MVP”，不是正式生产版本。已确认存在匿名管理接口、生产 Mock 风险、localhost 请求地址、隐私与注销缺口、交易数据一致性缺口、虚拟课程未履约、空白页面和大量未落地入口。

本计划按风险而不是按页面顺序推进。任何阶段都不能用“前端隐藏”替代后端安全控制。

## 2. 阶段划分

### 第一阶段：P0 安全与环境止血

- [ ] 管理接口默认拒绝，建立公开接口白名单和认证接口边界
- [ ] Mock Controller 仅在开发开关开启时加载
- [ ] 模拟支付、发货、退款增加后端开发开关
- [ ] 移除交易商品 `MockData` 回退
- [ ] 建立小程序环境配置，生产只允许 HTTPS 域名
- [ ] 添加生产配置启动校验，缺少必要环境变量时拒绝启动
- [ ] 修复购物车软删除唯一键冲突

验收：

1. 匿名访问管理接口返回 401/403。
2. 生产配置下所有 Mock 写接口不可用。
3. 正式小程序包中不存在 localhost、HTTP API 地址和测试支付入口。
4. 不存在的 SPU/SKU 无法加入购物车或下单。

### 第二阶段：P0 交易一致性

- [ ] 合并并复核支付状态机成果
- [ ] 合并并复核订单数据库分页成果
- [ ] 接入真实 SKU 读取与 SKU 库存服务
- [ ] 增加订单提交幂等键与唯一约束
- [ ] 增加支付通知流水、渠道交易号和支付单唯一约束
- [ ] 统一取消、超时、退款的库存处理
- [ ] 修复数据库迁移验收脚本

验收：

1. 重复下单、重复回调和并发取消不会产生重复订单、重复扣减或非法状态。
2. 退款后订单、支付单、退款单和库存一致。
3. 订单列表使用数据库分页且无逐单 N+1 查询。
4. 所有迁移可在隔离数据库首次执行和重复执行。

### 第三阶段：微信登录、隐私和账户能力

- [ ] 登录页面改为当前微信登录方式，不再依赖旧用户资料接口
- [ ] 增加用户协议、隐私政策、隐私同意记录和隐私设置入口
- [ ] 增加账号注销与数据删除流程
- [ ] 敏感字段日志清理、返回脱敏和存储保护
- [ ] Token 刷新并发收敛、设备会话管理和账号禁用即时失效

验收：

1. 用户可在登录前阅读协议并自主选择是否登录。
2. 拒绝非必要隐私授权仍可浏览公开内容。
3. 用户能提交注销并清理或匿名化法律允许删除的数据。
4. session_key、OpenID、完整手机号和地址不出现在客户端响应或普通日志中。

### 第四阶段：微信支付 V3 与可靠履约

- [ ] 支付适配层、微信 APIv3 下单和小程序调起参数
- [ ] 回调验签、解密、通知去重、金额/AppID/商户号校验
- [ ] 关单、查单、退款、退款通知和账单对账
- [ ] Outbox 事件和失败补偿
- [ ] 实物/虚拟订单拆分
- [ ] 课程支付后幂等生成权益

验收：

1. 以前端支付回调作为成功依据的路径全部移除。
2. 微信重复通知至少 10 次只完成一次业务变更。
3. 支付成功但履约失败可自动恢复或人工补偿。
4. 课程订单无地址/运费，支付成功后可以进入“我的课程”。

### 第五阶段：商品、售后与用户体验

- [ ] 服务端统一报价与优惠分摊
- [ ] 物流模板、自动收货和售后期限
- [ ] 明细级部分售后、退货物流和退款流水
- [ ] 评价与再次购买闭环
- [ ] 隐藏或完成会员、优惠券、分销、钱包等未实现入口
- [ ] 删除空白登录/注册/重置页面
- [ ] 请求防抖、分页结束、错误重试、弱网与支付处理中体验

验收：

1. 正式环境没有空白页、“开发中”、模拟按钮和伪数据。
2. 所有列表具有加载、空、失败、结束四种状态。
3. 所有资金和库存操作具备客户端防重与服务端幂等。

### 第六阶段：审核、性能与运维门禁

- [ ] 合法域名、HTTPS、备案、隐私保护指引和服务类目核对
- [ ] 商品文案和资质审核
- [ ] `sitemap.json`、分包、包体、图片和启动性能优化
- [ ] 健康检查、指标、告警、日志关联和任务互斥
- [ ] CI、单元、集成、并发、故障注入和真机回归
- [ ] 真实小额支付、退款、发货和课程权益演练

验收：

1. 微信开发者工具代码质量和体验检查无阻断项。
2. 自动化门禁全部通过。
3. 外部资料清单全部签字确认。
4. 先标记“可提审”，审核通过并完成生产演练后再标记“可上线”。

## 3. 本批次实施范围

本批次优先完成：

1. 后端管理接口与 Mock 能力生产隔离。
2. 小程序环境配置、隐私/协议入口、站点地图和空白路由收口。
3. 复核并合并已有支付状态机、订单分页、SKU 读取和库存服务成果。
4. 修复能够在本地复现的交易一致性问题。
5. 补齐对应自动化测试和状态文档。

微信商户资料、正式域名和行业资质不齐全时，只完成代码适配、启动校验和阻断清单，不使用虚假资料绕过。
