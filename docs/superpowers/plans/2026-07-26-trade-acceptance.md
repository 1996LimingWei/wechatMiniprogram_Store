# 交易闭环验收方案

> 日期：2026-07-26  
> 范围：微信小程序交易模块  
> 目标：给企业交付前的交易闭环提供固定、可重复、可追溯的验收标准。

---

## 1. 验收前置条件

1. 本项目专用 MySQL 已启动：`shop-mysql`，本机端口 `3307`
2. 本项目专用 Redis 已启动：`shop-redis`，本机端口 `6380`
3. 后端服务已启动：`http://127.0.0.1:8085`
4. 当前 `application-dev.yml` 使用本项目数据库和 Redis
5. 本地数据库已执行最新 `sql/init.sql` 或完成等价表结构迁移

---

## 2. 一键验收命令

在项目根目录执行：

```powershell
.\scripts\verify-trade-flow.ps1
```

如后端端口不同：

```powershell
.\scripts\verify-trade-flow.ps1 -BaseUrl "http://127.0.0.1:8085"
```

脚本会自动：

- 创建固定前缀测试用户
- 插入固定测试商品
- 创建测试地址
- 创建多条测试订单
- 调用小程序端交易接口
- 调用管理端订单/售后接口
- 校验数据库状态、库存、支付单、售后单和订单日志
- 结束后清理测试数据

---

## 3. 必验流程

### 3.1 下单与支付

验收点：

- 加入购物车成功
- 提交订单成功
- 预支付成功
- 支付成功后订单从待付款变为待发货
- 支付单从待支付变为已支付
- 商品库存扣减
- 写入创建订单和支付成功日志

### 3.2 管理端发货

验收点：

- 管理端订单列表能查到待发货订单
- 管理端订单详情包含商品、支付、地址、物流、售后、日志信息
- 管理端发货后订单变为待收货
- 物流公司和物流单号被保存
- 小程序端订单详情能看到物流
- 写入管理端发货日志

### 3.3 用户确认收货

验收点：

- 只有待收货订单允许确认收货
- 确认后订单变为已完成
- 写入确认收货日志

### 3.4 售后同意退款

验收点：

- 已支付订单可以申请售后
- 申请后订单变为退款中
- 管理端售后列表能查到处理中售后单
- 管理端同意后售后单变为已退款
- 订单支付状态变为已退款
- 写入退款完成日志

### 3.5 售后拒绝退款

验收点：

- 管理端拒绝售后时必须保存拒绝原因
- 售后单变为已拒绝
- 订单从退款中恢复到申请售后前状态
- 小程序端售后详情能返回拒绝原因
- 写入拒绝售后日志

### 3.6 用户撤销售后

验收点：

- 用户只能撤销处理中的售后申请
- 撤销后售后单变为已撤销
- 订单从退款中恢复到申请售后前状态
- 写入撤销售后日志

### 3.7 超时关闭与库存回补

验收点：

- 待付款订单过期后被系统自动关闭
- 关闭后订单状态为已取消
- 关闭原因记录为系统超时
- 库存只回补一次
- 支付单如存在则关闭
- 写入系统关闭日志

## 4. 企业交付口径

当前测试阶段允许继续使用 Mock 支付、Mock 物流轨迹和测试商品数据，但客户验收时必须满足：

- 用户端不出现“模拟”“Mock”“开发中”等内部字样
- 发货和售后审核由管理端接口处理
- 订单状态变化有日志可追溯
- 售后支持同意、拒绝、撤销三种结果
- 验收脚本可以重复执行，并且测试数据不污染客户数据
