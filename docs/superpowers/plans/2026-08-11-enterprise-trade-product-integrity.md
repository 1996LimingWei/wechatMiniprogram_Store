# 企业级交易与商品数据一致性加固计划

> 日期：2026-08-11
> 范围：商品、SKU、购物车、结算、订单、支付、退款、库存、销量、管理后台与数据对账
> 目标：消除数量、金额和状态静默错误，使前台展示、后台管理与交易事实使用同一份数据库数据。

## 一、验收原则

1. SKU 库存是可售库存的唯一事实来源，SPU 库存只允许由 SKU 汇总生成。
2. 前端只提交商品、规格、数量和幂等标识，价格、运费与实付金额全部由后端实时计算。
3. 商品基础信息与 SKU 必须在同一事务中保存，任何一步失败都不能留下半成品商品。
4. 已被购物车或未结束订单引用的 SKU 不允许删除或替换身份。
5. 支付、退款、订单、库存和销量变更必须幂等，并可通过脚本对账。
6. 上架商品必须至少存在一个价格、库存和规格数据合法的 SKU。

## 二、实施任务

### Task 1：库存与 SKU 身份收口

- 数据库 SKU 查询改为严格匹配 `spuId + skuId`，不再静默回退第一个规格。
- 扣减与回补库存统一走 `ProductInventoryService`。
- 每次 SKU 库存变化后同步 SPU 汇总库存。
- 库存计算使用溢出保护，拒绝负数、零价格和异常数量。

### Task 2：商品聚合保存

- 新增商品聚合保存接口，在一个事务内保存 SPU 和 SKU。
- 编辑时按 SKU ID 或规格属性匹配并保留已有 SKU ID。
- 库存更新使用旧库存条件，发现并发成交时拒绝后台覆盖。
- 删除规格或商品前检查购物车和未结束交易引用。
- SPU 售价、市场价与库存由有效 SKU 自动汇总。

### Task 3：销量与经营数据

- 支付成功后按订单明细增加商品销量。
- 全额退款成功后按订单明细冲减商品销量，最低为零。
- 看板销售额按支付时间统计，只统计仍处于已支付状态的订单。
- 热销商品按 SPU 汇总，避免同名商品被错误合并。

### Task 4：数据库约束与对账

- 增加库存、价格、购物车数量、订单金额和订单明细金额约束。
- 增加一个订单一个物流单的唯一约束。
- 提供只读对账脚本，检查库存汇总、订单金额、支付金额、退款状态和前后台商品可见性。

### Task 5：验证

- 商品模块与交易模块单元测试通过。
- 管理后台类型检查与生产构建通过。
- 增量迁移在本地 MySQL 执行成功。
- 真实接口验证前台商品均可在后台管理，并抽样跑通加购、结算、下单、取消与库存回补。

## 三、上线门禁

- 对账脚本必须零异常。
- 负库存、错误 SKU、金额不一致和重复业务请求必须被拒绝。
- 管理端编辑商品不能改变已有 SKU 身份或覆盖并发成交后的库存。
- 生产环境真实支付与退款仍需使用企业微信商户凭据完成小额联调后才能开放。
