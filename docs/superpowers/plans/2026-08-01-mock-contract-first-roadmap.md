# Mock 契约优先实施计划

> 对应规格：[Mock 契约优先与可替换数据源设计](../specs/2026-08-01-mock-contract-first-design.md)

## 阶段 1：冻结契约与安全边界

- [ ] 为商品/SKU、库存、支付、物流定义服务接口、响应对象、错误码和契约测试。
- [ ] 将现有 `MockData` 从 Controller/交易服务中抽离为独立 Mock Provider；Controller 和前端接口保持不变。
- [ ] 收紧管理端鉴权；按环境禁用 Mock 支付、发货和退款写操作。
- [ ] 修复迁移验收脚本和 Docker 配置，保证隔离环境可重复启动。

验收：匿名无法操作管理端；生产 profile 的 Mock 写请求被拒绝；同一 API 在 Mock/真实 Provider 下响应结构一致。

## 阶段 2：以 Mock 数据跑通完整真实规则

- [ ] 建立可复现 Mock 商品/SKU/规格/库存种子集，删除“商品不存在即回退”的逻辑。
- [ ] 让购物车、结算、订单仅使用商品与库存服务契约；下单重新校验 SKU、价格、上架状态和库存。
- [ ] 用 Mock 支付适配器复用现有支付状态机，覆盖重复支付、关闭后回调、金额异常和退款。
- [ ] 修复购物车软删除唯一键、退款时订单/支付单/库存一致性及无售后申请退款问题。

验收：Mock 数据下完整交易流程、异常流程和并发流程均由自动脚本覆盖；不存在 SKU、价格变化和库存不足均得到明确错误。

## 阶段 3：Mock 全页面闭环

- [ ] 补齐首页、搜索、品牌、专题、收藏、足迹、评论、地址、订单、售后所需 Mock 数据与空态。
- [ ] 小程序只保留正式 API 调用，移除页面内直读 MockData 与“开发中/模拟”文案。
- [ ] 补齐订单、支付、退款、库存、物流的回归脚本和测试数据清理。

验收：全量页面在 Mock Provider 下可演示；从浏览到售后的全部用户路径无接口缺失、无硬编码前端数据。

## 阶段 4：逐项替换真实数据源

1. 商品/SKU/库存：替换为 MySQL 实现，复用阶段 2 自动验收。
2. 首页与互动：替换为内容/互动表数据。
3. 物流：替换为物流供应商实现。
4. 支付与退款：在客户资料齐备后替换为微信支付 V3。

每项验收：开关灰度切换成功；契约测试、交易回归和隔离数据库迁移通过；生产环境不存在该能力的 Mock 写入口。

## 第一张开发任务单

先实施“商品/SKU Mock Provider 与库存契约”：定义稳定 SKU 数据、查询/校验/扣减/回补接口和契约测试；同时替换交易模块直接读取 SPU/回退 `MockData` 的调用。此任务完成后，其他所有交易能力均可在不依赖真实商品库的情况下继续开发。
