## 2. 执行摘要

当前项目已经完成从 Mock 商品演示系统向真实数据库交易系统的关键转变。商品、SKU、库存、购物车、下单、支付状态、发货、售后、退款、库存回补和数据对账已经形成真实链路，并具备较好的金额、库存和状态一致性基础。

当前不足主要不在“能不能下单”，而在以下四个层面：

1. 企业运营能力不完整：缺少账号角色管理、操作日志查询、库存流水工作台、资金对账、批量商品和订单操作。
2. 正式环境能力不完整：真实微信支付、退款和物流尚未使用客户凭据完成小额实单验收，生产编排、监控、备份和发布回滚没有闭环。
3. 产品表面与真实能力不一致：暂缓的会员权益仍公开展示，头像、手机号换绑和意见反馈等公开入口存在后端缺口。
4. 企业扩展模型未定义：当前采用单库存池、统一运费、整单单包裹模型，不具备多仓、拆包裹、区域运费和 WMS/ERP 能力。

本次完善的原则是先保证所有公开能力真实可用，再补企业运营后台，最后完成生产环境和真实资金验收。任何未闭环能力不得继续以菜单、按钮、页面文案或 API 的形式公开。

## 3. 交付目标与边界

### 3.1 本轮目标版本

本报告定义的企业基础交付版采用以下业务边界：

- 单企业主体、单小程序、单商户号。
- 单库存池，库存以 SKU 为最小单位。
- 一个订单一次整单发货、一个物流单号。
- 商品价格、优惠、运费和应付金额全部由服务端计算。
- 微信支付 API v3 作为正式支付和退款渠道。
- 快递 100 作为正式物流轨迹查询渠道。
- 管理端具备账号、角色、商品、库存、订单、售后、资金异常和审计操作能力。
- 所有资金、库存和状态变化可查询、可对账、可追踪到操作者。

### 3.2 本轮明确暂缓

会员模块继续按现有决定暂缓开发，包括付费会员、会员折扣、会员优惠券、会员等级权益和会员购买支付。

暂缓不等于继续公开半成品。本轮必须完成：

- 隐藏小程序会员中心、黄金会员和权益宣传入口。
- 隐藏管理后台会员菜单。
- 关闭或限制未完成的会员管理写接口。
- 不在结算、商品详情和个人中心展示未生效的折扣、优惠券、优先发货文案。
- 保留微信登录和交易所必需的基础用户身份、收货地址能力。

### 3.3 需要客户业务规则后才能实施的扩展项

以下能力不在规则不明确时直接编码，必须先确认业务规格：

- 多仓库存、仓库分配、调拨、采购和供应商管理。
- 一个订单拆分多个包裹、部分发货和多次发货。
- WMS、ERP、电子面单和财务系统对接。
- 区域、重量、件数、偏远地区和冷链运费模板。
- 电子发票、增值税发票和企业抬头审核。
- 优惠券、满减、会员价、活动叠加和优惠分摊。

这些项目列为企业增强版，不得在基础版页面或销售材料中宣称已支持。

## 5. 风险等级定义

| 等级 | 定义 | 处理原则 |
|------|------|----------|
| P0 | 可能造成资金、库存、敏感数据、越权或公开功能不可用；阻止生产上线 | 必须最先完成，全部通过后才能进入真实资金验收 |
| P1 | 不一定直接造成资金损失，但企业无法独立运营、审计或稳定交付 | 企业试运营前必须完成 |
| P2 | 提升运营效率、规模能力和客户适配范围 | 基础版稳定后按业务价值实施 |
| 外部阻断 | 依赖客户资质、账号、域名、证书或第三方合同 | 代码完成后仍需客户提供资料并联合验收 |

## 6. P0 生产上线阻断项

### P0-01 暂缓会员能力仍公开暴露

**现状**

- 小程序个人中心仍展示会员中心入口。
- 黄金会员页面宣传全场折扣、优先发货和每月优惠券。
- 管理后台仍展示会员管理菜单。
- 实际交易报价中优惠金额固定为零，没有会员权益计算和核销。

**风险**

- 页面承诺与实际交易结果不一致。
- 客户验收时会将暂未开放功能判断为系统故障。
- 可能形成价格、权益和消费者投诉风险。

**整改要求**

- 删除或通过统一功能开关隐藏所有会员和黄金卡入口。
- 生产环境强制关闭会员购买、会员权益和会员管理写接口。
- 商品、首页、个人中心和结算页不得出现未生效权益文案。
- 功能开关默认关闭，只有会员模块完整验收后才能启用。

**验收标准**

- 全局搜索和页面遍历中不存在可点击会员购买入口。
- 生产配置下调用会员购买接口返回明确的不可用状态且不产生数据变化。
- 结算金额不展示虚构优惠，商品详情不宣传未实现权益。

### P0-02 会员后台敏感字段泄露与批量赋值风险

**现状**

- 管理端分页直接返回数据库 `MemberUserDO`。
- 数据对象包含 `openid`、`unionid` 和 `sessionKey`。
- 更新接口直接接收 DO 并执行 `updateById`，可写入超出页面允许范围的字段。

**风险**

- 敏感身份凭据被序列化到浏览器。
- 管理员可通过构造请求修改 OpenID、会话密钥或会员等级等非授权字段。

**整改要求**

- 暂缓阶段关闭会员管理菜单和更新接口。
- 查询接口改为专用响应 VO，只返回业务必需且脱敏的字段。
- 更新接口改为专用请求 VO 和字段白名单。
- `sessionKey` 永远不得通过任何 API 返回或写入业务日志。

**验收标准**

- 自动化测试断言响应 JSON 不包含 `openid`、`unionid`、`sessionKey`。
- 传入额外字段不能修改数据库敏感列。
- 无会员管理权限的管理员访问接口返回真实 HTTP 403。

### P0-03 公开页面存在无后端支撑的功能

**现状**

- 头像上传调用不存在的 `upload/image`。
- 上传失败后会将 `wxfile://` 或临时路径写入数据库。
- 个人资料页手机号换绑缺少后端要求的隐私同意字段。
- 意见反馈调用 `feedback/save`，后端没有对应持久化接口。

**整改要求**

- 会员资料继续暂缓时，隐藏头像编辑和手机号换绑入口，保留只读基础资料。
- 不允许任何本地临时路径进入数据库。
- 实现真实意见反馈接口、数据表和管理后台处理页面；若本阶段不实现，则同步隐藏入口。
- 所有公开 API 建立前端声明到后端路由的契约检查。

**验收标准**

- 数据库头像列不接受 `wxfile://`、`http://tmp` 等临时地址。
- 小程序所有公开菜单点击后都有真实成功、空状态或明确关闭状态，不出现 404。
- API 契约检查不存在“前端已声明、后端无路由”的公开接口。

### P0-04 商品媒体无法由企业自主维护

**现状**

- 商品主图、轮播图、SKU 图和分类图标只能手工填写 URL。
- 没有对象存储上传、文件校验、素材记录和删除引用保护。

**风险**

- 企业运营人员无法独立上架商品。
- 外部图片失效会导致商品页大面积空图。
- 任意 URL 可能带来混合内容、恶意资源和版权问题。

**整改要求**

- 建立统一文件上传服务，支持兼容 S3 的对象存储或客户指定云存储。
- 增加文件类型、大小、扩展名、真实 MIME、图片尺寸和数量限制。
- 建立素材表，记录对象键、URL、哈希、大小、上传人、引用状态和创建时间。
- 管理后台使用上传控件、预览、替换和排序，不再要求手填 URL。
- 只有白名单 HTTPS 域名资源允许保存。

**验收标准**

- 管理员可完成上传图片、创建商品、小程序展示的完整链路。
- 非图片、超限文件和伪造 MIME 文件被拒绝。
- 被商品引用的素材不能被直接物理删除。

### P0-05 真实微信支付、退款和物流未验收

**现状**

- 微信支付和退款实现已存在，开发环境使用 Mock 验收。
- 快递 100 Provider 已存在，尚未使用客户正式凭据验收。

**整改要求**

- 注入客户 AppID、商户号、API v3 密钥、私钥、证书、支付回调域名。
- 注入快递 100 customer/key 并确认客户套餐和接口权限。
- 使用小额实单逐项验证支付、通知、查单、关单、退款和物流。
- 所有实单验收数据保留订单号、支付单号、退款单号和日志证据，不记录密钥。

**验收场景**

1. 正常支付成功并收到回调。
2. 小程序支付成功但回调延迟，由主动查单补齐。
3. 重复支付通知不重复增加销量或修改库存。
4. 金额、AppID、商户号或币种不匹配时拒绝处理。
5. 待付款超时后本地关单和微信关单一致。
6. 仅退款成功、处理中、明确失败和网络超时。
7. 退货退款在商家收货后发起并最终一致。
8. 物流公司编码、单号和轨迹查询成功。

**通过标准**

- 订单、支付、退款、销量和库存对账异常数全部为零。
- 所有重复通知和重试均满足幂等要求。
- 异常场景可自动恢复或在后台形成可处理任务。

### P0-06 缺少企业资金和异常处理工作台

**现状**

- 后端有支付主动查单和退款重试任务。
- 管理员只能在订单或售后详情中零散查看状态。
- 没有支付异常、退款异常、任务积压和金额不一致的集中页面。

**整改要求**

- 新增资金对账概览、支付异常、退款异常和任务积压页面。
- 支持按订单号、支付单号、退款单号、用户、状态和时间筛选。
- 显示本地金额、渠道金额、尝试次数、下次执行时间和最后错误。
- 提供受权限控制的人工查单、人工同步和问题标记功能。
- 每个操作必须写入操作日志，不允许直接修改金额或强行标记成功。

**验收标准**

- 构造支付处理中、退款失败和重试耗尽数据后均可在后台定位。
- 人工同步重复执行不产生重复退款或重复状态变化。
- 每日对账脚本和页面统计口径一致。

### P0-07 生产部署形态仍是开发环境

**现状**

- 根目录 `docker-compose.yml` 使用 `dev` profile、默认密码和 Mock Provider。
- 编排中没有管理后台服务。
- 没有生产环境标准部署模板和密钥注入说明。

**整改要求**

- 保留现有开发编排，新增独立生产编排，不得混用。
- 生产编排包括管理后台、后端、MySQL/外部数据库、Redis、反向代理和健康检查。
- 所有敏感配置从部署平台 Secret 或环境变量注入。
- 生产启动必须强制关闭 Mock、默认管理员口令和通配 CORS。
- 提供 HTTPS、域名、回调地址、日志目录、数据目录和滚动发布说明。

**验收标准**

- 使用空白生产配置启动时必须失败并列出缺失项。
- 注入完整测试凭据后可在隔离环境按 `prod` profile 启动。
- 生产镜像内不包含源码、测试数据、私钥或开发日志。

## 7. P1 企业运营必备项

### P1-01 管理员账号、角色与权限中心

**目标功能**

- 管理员列表、创建、禁用、解锁、重置密码和强制下线。
- 角色列表、角色权限配置、账号绑定角色。
- 当前管理员修改密码。
- 菜单和按钮根据权限代码显示或隐藏。
- 超级管理员关键操作二次确认。

**约束**

- 不能删除或禁用系统最后一个可用超级管理员。
- 密码修改或重置后使旧 Token 全部失效。
- 不在前端保存完整权限规则，后端始终作为最终授权边界。

**验收标准**

- 商品运营、订单客服、售后审核和超级管理员四类角色可独立配置。
- 越权按钮不可见，直接调用接口仍返回 403。
- 所有账号和权限变更有审计记录。

### P1-02 登录日志、操作日志和审计中心

**目标功能**

- 查询登录时间、账号、IP、结果和失败原因。
- 查询操作者、模块、请求方法、资源、结果、耗时和时间。
- 支持订单号、商品 ID、售后单号等业务标识关联。
- 敏感字段、Token、密码、证书和完整个人信息不进入日志。

**验收标准**

- 关键商品、库存、订单、售后、权限操作均能追溯到管理员。
- 日志查询接口只读，业务管理员不能删除或修改审计记录。

### P1-03 商品批量运营能力

**目标功能**

- 商品 Excel/CSV 模板下载、预校验、导入结果和失败明细。
- 商品导出。
- 批量上架、下架、调整分类和排序。
- 批量调价与库存调整必须填写原因并二次确认。
- 批量操作设置数量上限，采用逐项结果而不是整批静默失败。

**验收标准**

- 错误行不会污染正确数据。
- 批量调库存后库存流水逐笔连续。
- 批量下架后小程序和购物车实时反映失效状态。

### P1-04 库存运营工作台

**目标功能**

- SKU 当前库存、库存预警值、最近变化和可售状态查询。
- 库存流水按 SKU、商品、业务类型、业务单号、操作者和时间查询。
- 人工调整库存必须填写原因并使用条件更新。
- 提供库存对账结果和异常提示。

**验收标准**

- 当前库存等于期初库存加全部流水变化。
- 并发下单和后台调库存不能产生负库存或丢失更新。
- 流水只允许追加，不允许编辑和删除。

### P1-05 订单运营增强

**目标功能**

- 订单导出，导出字段按权限脱敏。
- 发货单和拣货单打印。
- 批量发货导入与逐单校验。
- 收货信息按权限查看，默认脱敏。
- 订单备注区分用户备注和内部备注，内部备注记录操作者。
- 高风险操作采用二次确认和幂等请求号。

**验收标准**

- 批量发货中一条错误不影响其他合法订单。
- 同一订单不能重复发货。
- 非订单岗位无法导出完整手机号和地址。

### P1-06 运费规则可运营化

基础版先完成全局运费配置后台化：

- 基础运费、免邮门槛、启停状态和生效时间。
- 修改记录和历史值审计。
- 结算和下单使用同一个服务端规则源。

区域、重量和偏远地区模板进入增强版，需先确认客户配送规则。

**验收标准**

- 后台修改规则后，新订单按新规则报价，历史订单金额不变化。
- 非法负数、金额溢出和免邮边界有自动化测试。

### P1-07 意见反馈与帮助内容管理

**目标功能**

- 意见反馈提交、查询、状态、处理备注和处理人。
- 防重复提交、文本长度和联系方式校验。
- 帮助分类和帮助文章后台 CRUD，不再硬编码在 Controller。
- 小程序支持加载、空状态和失败重试。

**验收标准**

- 用户提交后后台可查询并处理。
- 管理员处理记录可审计。
- 帮助内容修改无需重新发布后端代码。

### P1-08 API 契约和输入校验统一

**整改要求**

- 查询统一使用 GET，状态变更统一使用 POST/PUT/DELETE。
- 写接口不再使用无方法限制的 `@RequestMapping`。
- Controller 不直接接收 DO 或任意 Map，统一使用 ReqVO/RespVO。
- 数量、金额、分页、字符串和枚举全部设置边界。
- API 返回真实 HTTP 401、403、404、405 和 500 状态。
- 生成并维护 OpenAPI 契约，前后端类型从契约或统一类型源校验。

**验收标准**

- 错误 HTTP 方法返回 405。
- 未知字段不能覆盖数据库列。
- 前端公开 API 声明与后端路由不存在缺失或参数漂移。

### P1-10 可观测性与告警

**目标能力**

- 每个请求生成或透传 Request ID。
- 日志关联订单号、支付单号、退款单号和售后单号。
- 暴露登录失败、下单失败、库存扣减失败、支付回调失败、退款任务积压、任务耗时和接口延迟指标。
- 建立 Prometheus 或客户监控平台采集规则。
- 建立邮件、短信、企业微信或客户指定渠道告警。

**最低告警项**

- 支付通知连续失败。
- 退款自动尝试耗尽。
- 库存对账异常不为零。
- 支付/订单金额对账异常不为零。
- 定时任务长时间未成功执行。
- 数据库、Redis、磁盘或服务健康异常。

### P1-11 备份、恢复与发布回滚

**目标能力**

- MySQL 定时全量备份和 Binlog 增量恢复。
- 对象存储版本或生命周期保护。
- 备份文件加密、异地保存和保留周期配置。
- 每个生产迁移执行前自动备份并验证目标数据库。
- 提供应用版本回滚和数据库前向修复方案。

**建议基线**

- 数据恢复点目标 RPO 不高于 15 分钟。
- 服务恢复时间目标 RTO 不高于 2 小时。
- 至少完成一次隔离环境恢复演练并记录恢复耗时和数据校验结果。

### P1-12 性能、容量与稳定性测试

**测试范围**

- 商品列表和详情。
- 购物车和结算。
- 并发下单和库存争抢。
- 支付重复通知。
- 退款任务批处理。
- 后台订单和售后分页。

**建议基线**

- 100 个并发用户持续 30 分钟，业务错误率低于 0.1%。
- 常用读取接口 P95 不高于 500ms，核心写接口 P95 不高于 800ms，不包含微信和物流第三方耗时。
- 高并发争抢库存时不超卖、不负库存、不重复订单。
- 压测后执行全部数据对账，异常数为零。

最终指标应根据客户预计日订单量和峰值流量调整。

## 10. 数据一致性强制规则

后续所有整改不得破坏以下规则：

1. 金额统一使用整数分，禁止使用浮点数参与计算和持久化。
2. 订单实付金额等于商品金额加运费减优惠金额。
3. 订单明细金额、订单金额、支付金额和退款累计金额可相互对账。
4. SKU 库存不得为负，SPU 库存等于有效 SKU 库存汇总。
5. 所有库存变化必须产生唯一、不可变流水。
6. 支付、退款、发货和售后命令必须幂等。
7. 历史订单使用下单快照，不受商品后续改价、改名或下架影响。
8. 退款成功前不得提前把资金状态标记为已退款。
9. 已完成订单的完成时间不可因普通更新发生漂移。
10. 任何人工补偿必须记录操作者、原因、前后状态和关联业务单号。

## 11. 安全与隐私强制规则

1. 密码、Token、AppSecret、API v3 密钥、私钥、证书和 `sessionKey` 不得返回前端或写入日志。
2. 手机号、地址、OpenID 等个人信息按岗位最小化展示并默认脱敏。
3. 所有管理端数据接口同时校验登录、账号状态、角色和权限。
4. 前端隐藏按钮不能替代后端权限校验。
5. 所有修改接口使用字段白名单，禁止直接接收数据库 DO。
6. 文件上传校验类型、大小、内容和存储域名，不允许用户控制对象路径。
7. 导出文件设置权限、数量上限、有效期和下载审计。
8. 生产环境禁止默认密码、Mock、通配 CORS 和 HTTP 回调地址。
9. 用户协议、隐私政策和实际采集字段必须一致。
10. 正式提审前重新核对微信平台当期隐私、类目和支付规则。
