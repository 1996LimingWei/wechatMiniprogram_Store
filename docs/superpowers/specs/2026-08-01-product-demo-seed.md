# Issue #24 商品内容演示种子与自动验收数据集规格

> 日期：2026-08-01
> 状态：已确认
> Issue：[GitHub #24](https://github.com/QtImM/wechatMiniprogram_Store/issues/24)

## 目标

提供一套可重复初始化、可强制重放且关联完整的数据库演示种子，使全新 Docker 环境无需人工补数据即可演示商品浏览、搜索、多规格、缺货、首页内容和评论。

## 数据范围

- 使用稳定 `24xxxx` ID，避开历史自增种子和自动验收临时数据。
- 覆盖多个一级、二级分类，每个演示二级分类至少有一件上架商品。
- 覆盖新品、热销、普通和下架商品。
- 覆盖单规格、二维多规格、部分组合缺货和全部缺货商品。
- 多规格 SKU 具备不同价格、图片和库存，并使用完整 `properties` JSON。
- 覆盖 Banner、频道、品牌、专题、分类楼层所需内容。
- 覆盖搜索关键词和一组非真实个人信息的演示评论。

## 幂等规则

- 新增独立版本迁移，不修改历史迁移。
- 所有种子使用稳定主键和 `INSERT ... ON DUPLICATE KEY UPDATE`。
- 强制重放迁移只更新种子，不新增重复商品、SKU、内容或评论。
- 不删除或覆盖非本迁移稳定 ID 的业务数据。

## 验收标准

- 隔离数据库执行全部迁移成功，强制重放演示种子后数量不变。
- 商品、SKU、分类、评论与内容记录不存在孤儿关联。
- 至少一件二维多规格商品有可购买组合和缺货组合；至少一件商品全部缺货。
- 首页、分类、搜索联想、商品列表和详情接口返回演示数据。
- 商品详情返回稳定规格维度、不同 SKU 价格/图片/库存与正确可售状态。
- `scripts/verify-db-migration.ps1`、商品模块测试、Docker 全量构建和商品种子 HTTP 验收通过。
- Docker 持久化数据继续位于仓库 D 盘 `.docker-data`。

## 非目标

- 不导入真实客户数据或个人信息。
- 不实现后台录入、Excel 导入、对象存储或第三方图片 API。
- 不修改支付、物流、订单状态机或小程序页面。
