# 商品真实接口与本地数据库迁移设计

> 日期：2026-07-27
> 类型：Epic 设计规格
> 状态：待评审

## 1. 背景与目标

交易闭环 P0 已完成，但商品分类、列表与详情接口仍依赖 `MockData`，且已有本地 `shop` 数据库未包含部分新增交易表。下一阶段先建立可重复执行的数据库增量迁移，并将商品核心读取接口切换到数据库，作为库存、商品快照与支付 P1 的稳定基础。

本 Epic 的目标是：在不重置已有数据库数据的前提下，让小程序在 `useMock: false` 时从数据库读取商品核心信息，并让本地开发环境可安全升级到当前交易表结构。

## 2. 范围

### 2.1 数据库增量迁移

- 新增 `sql/migrations/`，迁移文件按版本顺序命名，例如 `V20260727_01__trade_schema.sql`。
- 迁移必须可追踪：记录已执行版本，重复运行时跳过已完成迁移。
- 将缺失的交易表和字段拆分为增量 SQL，至少覆盖：`trade_after_sale`、`trade_order_log`、相关索引及售后状态字段。
- 禁止通过重新执行 `sql/init.sql` 初始化已有数据库；`init.sql` 仅用于全新数据库。
- 迁移失败时停止后续迁移并输出明确的版本与错误信息。

### 2.2 商品真实读取接口

- 分类接口：提供分类树、当前分类和分类详情，兼容现有小程序路径。
- 商品列表：支持分类筛选、关键词、分页、新品与热销筛选；分页必须在数据库执行。
- 商品详情：返回 SPU、SKU、规格、库存、轮播图和详情内容的最小可用数据。
- 商品相关接口：基于同分类商品返回有限数量的推荐结果。
- 首批实现只覆盖商品读取链路；品牌、专题、收藏、搜索历史不纳入本 Epic。

### 2.3 小程序与交易衔接

- `useMock: false` 时，分类、商品列表和详情页不得回退到 `MockData`。
- 交易商品快照优先读取数据库商品和 SKU；不存在的商品应返回明确业务错误，不得回退为演示商品。
- 保留已有演示商品种子数据，供全新本地数据库初始化与验收使用。

## 3. 非目标

- 不接入微信支付 V3 或真实退款。
- 不实现营销、收藏、商品评价、品牌和专题的真实化。
- 不实现完整后台商品运营页面。
- 不在本 Epic 内重构现有小程序页面视觉或路由。

## 4. 实施边界与依赖

- 运行环境必须使用 JDK 25；JDK 17 不支持当前 Maven 的 Java 25 编译目标。
- MySQL 使用项目专用容器 `shop-mysql`（宿主机端口 `3307`）。
- 迁移执行前必须备份或确认目标数据库，迁移脚本不得包含删库、删表或重置数据操作。
- 接口响应继续使用 `{code, msg, data}` 统一格式；登录态与私有数据读取遵循现有 SecurityContext 约定。

## 5. 验收标准

1. 在 JDK 25 环境执行 `cd shop-backend && mvn clean install -DskipTests` 成功。
2. 空数据库可通过 `sql/init.sql` 初始化；已有数据库可通过迁移升级，重复执行不产生重复表、字段或数据破坏。
3. 升级后数据库包含 `trade_after_sale`、`trade_order_log` 及其代码依赖的字段和索引。
4. 小程序 `useMock: false` 时，分类、商品列表和商品详情均读取数据库数据，且不存在 `MockData` 回退。
5. 列表分页、分类筛选和关键词搜索均在数据库层执行。
6. 下单及结算读取数据库商品/SKU，商品不存在、下架或库存不足时返回明确错误。

## 6. 子 Issue 拆分

1. `chore: 建立数据库增量迁移机制并补齐交易表结构`
2. `feat: 实现商品分类与商品列表真实接口`
3. `feat: 实现商品详情、SKU 库存与交易快照对接`
4. `test: 补充真实商品链路与数据库迁移验收`

## 7. 评审结论

本规格经评审后，按上述顺序创建子 Issue。第一个子 Issue 完成并验证迁移安全性后，再进入商品接口真实化，避免在不一致数据库结构上继续开发。
