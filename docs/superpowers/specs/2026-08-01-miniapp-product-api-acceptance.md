# Issue #25 小程序商品正式 API 收口与端到端验收规格

> 日期：2026-08-01
> 状态：已确认
> Issue：[GitHub #25](https://github.com/QtImM/wechatMiniprogram_Store/issues/25)

## 目标

让首页、分类、搜索、商品列表、商品详情、收藏、足迹和评论只通过 `utils/api.js` 中的正式 API 访问本地 Docker/MySQL 数据，不再存在商品内容本地 Mock、伪造业务数据兜底或无效 SKU 快捷加购。

## 数据与交互边界

- 请求层始终访问 `http://127.0.0.1:8085/app-api/`，删除全局 `useMock` 分支和 `utils/mock.js`。
- 保留后端明确返回 `mockPay=true` 时的受控开发支付页面，不保留绕过后端预支付的前端 Mock 支付入口。
- 商品详情只展示接口返回的商品、SKU、评论、属性与关联商品；删除页面内按商品 ID 硬编码的药食百科和搭配商品。
- 首页和分类页不使用固定 `productId=1` 加购；列表入口统一进入详情选择真实 SKU。
- 请求失败必须拒绝 Promise，并提供明确网络或服务错误提示；页面不得用本地商品数据兜底。
- 未登录的收藏、足迹和发表评论继续由正式接口鉴权处理，并引导用户登录。

## 验收范围

- 静态检查商品内容页面无 `mock.js`、`useMock`、固定 SKU 和商品业务字典依赖。
- HTTP 回归覆盖首页、分类、搜索、详情、多规格/缺货、登录、收藏、足迹、评论发表与清理。
- 小程序构建产物不得包含商品内容 Mock 路由或 `useMock` 请求分支。
- 使用 HBuilderX 编译到微信小程序；若当前环境可调用微信开发者工具，则完成自动预览/打开检查，否则保留明确的人工开发者工具验收清单，不虚构 GUI 结果。

## 非目标

- 不实现微信支付 V3、真实物流或管理后台前端。
- 不移除后端环境守卫控制的开发态 Mock 支付、发货和退款能力。
- 不升级 uni-app Vue2 技术栈，不新增会员、分销或钱包功能。
